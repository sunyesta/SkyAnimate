# Open Animate — Feature Spec & Roadmap

Oct 18, 2026 · @Mary

## Overview

Open Animate is a private, Windows-only desktop app for 2D cut-out and vector animation: Moho's animation model inside Blender's interface and editing habits, written like Blender in C++ with an embedded Python API.

**What it takes from each**

| From Moho | From Blender |
| --- | --- |
| Smart actions (smart bones) | Fast, lag-free viewport and rendering |
| Simple layer system: groups, bones, switch layers | Mirror modifier for armatures and drawings |
| Masking | Grease Pencil-style layer masks |
| Vector drawing and point tools | Free 3D view outside the camera; imported meshes |
| Bone binding and rigging tools | Modular editors with split views |
|  | Layout and theme; a better timeline |
|  | Modal tools and shortcuts: G move, E extrude |
|  | Custom bone shapes |

**Guiding principles**

- **Moho's data model, Blender's interaction model.** Layers, bones and smart actions behave like Moho; tools, keymaps and editors feel like Blender.
- **Everything is an operator.** Every action is a named command that keymaps, menus, undo and Python all share.
- **Python is first-class.** Tools, panels and add-ons can be written in Python, the way Moho tools are Lua scripts.
- **Small first.** Each milestone ships something usable before the next one starts.

**Not in scope:** public release, macOS and Linux builds, 3D modelling, sculpting, physics simulation, a node-based compositor, or Moho file compatibility.

**Sources:** the Moho scripting API docs scraped from mohoscripting.com, community and built-in Moho Lua tool scripts, and the Blender source tree, all in the project folder. The app is private, so Blender's GPL license only matters if it is ever distributed.

## Core concepts

The data model follows Moho: a document holds a tree of layers, almost every property is an animated channel, and actions are alternative timelines stored inside those channels. Smart bones fall out of that design almost for free.

**Document.** Frame range, frame rate, canvas size (the Document tab's Resolution: W and H with a link button between them; linked, changing one changes the other, keeping the proportion they had when linked; saved with the file; Python: document.resolution_linked), background colour, a 3D camera (track, zoom, roll, pan/tilt channels), timeline markers, a shared style library and layer comps (saved sets of visible layers). Frame 0 is the rigging frame: the rest pose, never rendered.

**Setup frame (frame 0).** Open Animate keeps Moho's model: frame 0 holds the setup pose, and there are no separate rest and pose modes. Smart bones need this, because a smart action's effect is measured from its frame-0 values. Blender's clear sense of mode is added on top:

- **Setup toggle** in the viewport header, with a shortcut: it jumps to frame 0, and pressing it again returns to the frame you were on.
- **Clear signals on frame 0:** a red border on the viewport and the timeline (and a red playhead), a "Setup" label in the header, and frame 0 drawn apart at the start of the timeline.
- **Rigging tools only work on frame 0**, as in Moho: adding bones, binding points and layers, bone strength. Elsewhere they are greyed out with the tooltip "Switch to Setup (frame 0)". Each of the toolbar's boxes has its tools for every frame, then under a bar its frame-0 tools (Draw, Shape, Split Curve, Weight Select, Weight Paint), greyed out on other frames with the reason ("Setup frame only: press Tab to go to frame 0"); a frame-0 tool picked stays picked there, greyed out, and a click with it (or its shortcut) says so (see Viewport toolbar).
- **Auto-keying never applies on frame 0**, because changes there edit the setup pose and carry into every frame.
- **Keys are changes from the setup pose**, as Blender's pose bones and shape keys, Spine's deform keys and Harmony's deformers keep them (Moho keeps own values): a bone's keys hold its Transform (along the bone's rest axes) and Angle; a point's its Transform, applied before bones bend the drawing, so a keyed shape follows the bones; a handle's its Handle Angle and Length (the turn, and the length added), so a handle swings along an arc between keys. Away from frame 0 the Properties editor shows these, 0 at rest: the Bone panel's Transform and Angle, the Point and Shape panels' Transform, and the Point panel's Handle In and Handle Out Angle and Length (an aligned partner turns with it). Reshaping frame 0 after animating keeps every pose's motion. A point added to an animated curve (Split Curve) takes its neighbours' motion, blended by distance along the curve (past an end, the end's), so adding points doesn't break the animation. Older files and Moho imports open converted.

**Layers.** Every layer has a name, a stable ID, visibility, lock, label colour, an origin, animated transform channels (position, scale, X/Y/Z rotation, shear, flip), opacity, blend mode, masks, an optional parent bone, a timing offset and a modifier stack. Types for our app:

| Layer type | Holds | Version |
| --- | --- | --- |
| Vector | Points, curves, shapes and styles | v1 |
| Group | Child layers; its masks apply to everything in it | v1 |
| Bone | A group that owns a skeleton and controls its children | v1 |
| Switch | A group that shows one of its children (or none) per frame, chosen by a held key that names the child | v1 |
| Media | Images, image sequences, video and sound, as clips along the timeline; a Guide by default (shown while you work, never rendered) | v1 |
| Mesh 3D | An imported OBJ or glTF mesh placed in the scene | Later |
| Text | Text kept as typed, its letters made into vector shapes (each a shape with the run's look, holes and all): click its text to type on the canvas, the Text tab sets fonts, looks and layout, Convert to Vectors makes ordinary vector layers of it | v1 |
| Particle | Child layers emitted as particles | Maybe |
| Note | A sticky note in the viewport | Maybe |

**Vector drawings.** A drawing is a pool of points, curves through those points, and shapes. A point can sit on several curves, which is how Moho welds lines together. Each point has an animated position, an animated width and an optional bone binding. Every curve point has two Bezier handles, and every handle is free, like Blender's Free handles: stored, and moved only by hand (or with its point). A new point gets its handles once, from Moho's smooth spline (curvature, weight and offset) or, at corners and straight sides, a third of the way toward its neighbours. Align (right-click a selected point or handle) lines a point's handles up and keeps them in line: moving one turns the other. Right-clicking selected points edited from another layer (a bone layer, or several layers at once) also offers Select Layers of Selected Points: the layer holding them becomes active (others with selected points are picked), the points staying selected. Alt-dragging a handle moves it alone and unaligns the point; Unalign does the same without moving anything. Peak and Smooth (no longer in any menu; Python: oanim.ops.mesh.peak(), mesh.smooth()) set a point's handles once (straight, or smooth and aligned). **Smooth Points** (right-click with points selected; Blender's Smooth Vertices, for curves) evens out the selected points: each goes toward the middle of its neighbours along its curves (a welded point averages every curve's), half its Smoothing of the way (so 1 takes a zigzag flat in one go), and its handles as far toward smooth ones (in line along the way from the point before to the one after, each a third of its side long; at 1 they stay aligned); unselected points hold, and open curves' ends stay unless Smooth Endpoints is on. The ViewportActionPanel has Smoothing (0.5), Repeat (1), Position, Handles, Radius (evens the line's width; off), Keep Shape (Taubin's push back out after each step, so a closed shape doesn't shrink; off) and Smooth Endpoints (off), and Keep Poses on the setup frame. It smooths what shows, through the bones, follows mirror editing, on a detail level smooths the points that level shows, and away from frame 0 poses them (auto-key keys it). Python: oanim.ops.mesh.smooth_points(factor=, repeat=, position=, handles=, radius=, keep_shape=, ends=). **Separate** (P, Blender's Separate > Selection) moves the selected points, the curve pieces between them and the shapes those pieces fully cover (what Shift D would copy; a shape they cover only part of gives them a shape of their own in its look: a piece of a stroke keeps its line, without the fill it can't close, and a piece of a fill with no line stays a fill with no line, showing once closed, never gaining a stroke; Shift D leaves no handle picked on its own behind, so moving the copy can't swing the original's handles) into a new layer just above, in the same group, named after it (Face 1) with its settings, bone binding and keys; the original loses those pieces, keeping points that its other curves still use, and stays the one being edited. One undo step; Python: oanim.ops.mesh.separate(). M opens the Merge menu (Blender's, for points): Merge makes the selected points one point at their middle, and Merge by Distance does so for the selected points within Merge Distance (0.001, in the Adjust Last Operation panel) of one another, each group at its middle. Curves through merged points run through the one kept, a segment between two of them goes (a shape along it carrying on across), and shapes that met only at some of them become one, a line with a line and a fill with a fill, in the first one's look (a fill and its outline on the same curve stay as they are). Python: oanim.ops.mesh.merge(), mesh.merge_by_distance(distance=). With one point selected, the Vector tab's Selected Points panel shows its handles as **Handle In** and **Handle Out** rows, each an Angle (degrees, counter-clockwise from the layer's x axis) and a Length (how far it reaches from the point), as Moho and Illustrator give handles; an open curve's first point has no In row and its last no Out; a point on several curves shows each curve's, numbered; a handle picked on its own shows just its row. Changing one moves the handle (an aligned partner turns with it), one undo step (Move Handle); away from frame 0 they show how far the handle has turned and grown from the setup pose instead, 0 at rest. A **Transform Points** tool in the toolbar (for drawings; any frame) puts the same box gizmo Transform Bones has round the selected points and handles picked on their own, in the active layer's space: drag inside to move (Shift keeps to one axis, Ctrl snaps to a point), the band around it to turn about the pivot (Shift: 45° steps), a handle to scale (Alt from the pivot, Shift keeps a corner's proportions); Ctrl on a side handle shears instead (as Illustrator's and Inkscape's: a top or bottom handle slants the points along x, a left or right one along y, the opposite side staying, or the pivot with Alt; the cursor shows the way, and the undo step is Shear Points); while the box moves, turns, scales or shears them, the points and handles aren't drawn, so the shape is what's seen; curve handles don't show (nor can be picked) while it is the tool, and with the overlays off (Shift Z) the box, as Transform Bones' box, isn't drawn and clicks select, the pivot to move it (Ctrl snaps to a point); outside, a click selects and a drag box-selects. Points move as G, R and S move them: across every edited layer, through their bones, with mirror and proportional editing, keyed away from frame 0. Its header has the mode switch (Transform, Distort, Warp), Position (the pivot), Scale, Angle, Shear, Flip H, Flip V and Symmetrize; they run mesh.transform_selected (move_x/y, scale_x/y, angle, pivot_x/y). Its look, edge shear, Distort, Warp and the turning knob are under Box gizmos. **Mirror** (right-click with points selected, a submenu as Blender's: X Global, Y Global, X Local, Y Local) flips the selected points, and handles picked on their own: Global along the document's axes through their layer's origin (each layer's own, when several are edited), Local along the active layer's own axes (turning with it) through the middle of the selection; through their bones, with mirror and proportional editing, keyed away from frame 0, one undo step ("Mirror X Global"), the options in the ViewportActionPanel; Python: oanim.ops.transform.mirror(axis="X" or "Y", orientation="GLOBAL" or "LOCAL"). **Symmetrize** (right-click with points selected) makes the selected points mirror images across the layer's vertical axis, copying one side onto the other (Right to Left by default): points within the Threshold of the axis snap onto it and their two handles mirror each other (made flat when within 10° of flat, so one point on the axis just evens its handles); the others pair up by where each one's reflection lands nearest in the setup pose, and each copy takes its partner's place, handles (reflected), width and corner (and, with Weights, its bone weights, _L and _R swapped). Each side needs as many points as the other: otherwise nothing changes, the status bar warns ("Uneven sides: 2 on the right, 1 on the left") and the points without a partner are selected. On frame 0 it reshapes the drawing; on other frames it mirrors the pose (each copy's Transform becomes its partner's, reflected, and auto-key keys it). The copied side's shapes give their look to their images (Fill and Outline, colours, width, brush and material; a shape that is its own image keeps its own), across a sided pair too. In a sided layer (Ear_L) it works across the pair instead: its selected points and the partner's points nearest their reflections (one each) become mirror images across the pair's axis, Direction saying which side is copied (Right to Left copies the +x one), Threshold and Weights as above; with more selected than the partner has points to pair, nothing changes and the status bar says so. Viewport Overlays > Handles shows None, Selected, Shape (the default: every handle of the shapes being worked on, any of whose points is selected) or All; Point Size and Handle Size under it (pixels across, 2 to 24; 6 and 6.5 by default, as Blender's Vertex Size) set how big points and handles' ends are drawn, a click within 16 pixels of one (or 8 past a bigger one) picking the nearest point or handle; Edges selection mode shows none, as it picks segments rather than points. A shape is a list of curve segments with a fill and outline style. Styles cascade: a shape has its own style plus up to two shared styles from the library.

**Holes.** A shape can be several loops filling together, as Moho's shapes with holes and SVG's compound paths: its **Fill Rule** (the Shape panel, shown for a shape of several loops) says how. **Even-Odd**: a loop inside another is a hole (and one inside that filled again), whichever way it was drawn; **Nonzero**: each loop's direction counts, so one drawn the other way round is a hole and one the same way adds to the fill (how fonts are made, their overlapping strokes staying filled); **Each Loop**: every loop filled on its own, holes filled over (what shapes of several loops were before holes, and what files from then keep). One shape: one look and material, one click to select, and a click in a hole picks what is behind it; its outline goes round every loop. **Join Fills** (F with whole loops selected, as Blender's F makes a face of a loop and Moho's Create Shape takes an outline and its holes; or the right-click menu) makes one shape of the selected shapes that go round, Even-Odd, with the first one's look; **Separate Fills** (right-click) splits a shape of several loops into a shape each. Holes show in renders, masks, End Lines at Edge, picking and the Boolean modifier (which joins shapes with holes and keeps the holes of what it makes). Fills are worked out with Clipper2 and cut into triangles with earcut. Python: layer.shape_style(i)['fill_rule'], layer.set_shape_style(i, fill_rule="EVEN_ODD" or "NONZERO" or "LOOPS"), oanim.ops.mesh.join_fills(), mesh.separate_fills(); oanim.layers_at((x, y)) gives the layers drawn at a point.

**Text layers.** Text kept as typed, as Blender's text objects (Moho's text layers): runs of it, each with a font (any installed family), weight (Thin to Black), italic, size (document units) and a shape's look (Fill and Outline, colours, line width and brush, or a shared material: a run linked to one changes with every shape using it). Its letters are made with DirectWrite (Windows' text engine: kerning, ligatures, right-to-left scripts, letters a font lacks taken from another) into the layer's drawing, a shape per letter named after it, filling Nonzero, made again whenever the text, its fonts, layout or materials change (from the Text tab, typing, Python or a driver). The letters are saved with it, so a file shows its text where the font isn't installed (the Text tab says which fonts are missing). Layout: Align (Left, Center, Right, Justify), Line Spacing (a multiple of the font's own), Letter Spacing and Word Spacing (ems), Shear (a slant about each line's baseline) and Box Width (0: point text, lines breaking only at new lines; else lines wrap at it). Its origin is the first line's top: for point text on its left end, middle or right end as aligned, for a box its left edge. It moves, turns, scales, fades, masks and follows bones as a layer: G, R and S move, turn and scale it as a whole (as a Media layer, about its origin), and **Don't Auto Key** (the Text tab's Layout, on by default) keeps moving, turning, scaling or fading it from setting keys whatever the record button says (keying it by hand still does); its points aren't edited. **Typing** with Transform Layer and Edit Text (the tools a text layer has: Select has nothing to pick there): Transform Layer, the one a text layer starts with, moves, turns and scales it with its box gizmo, and a double-click on the text starts typing there (Edit Text picked); with Edit Text, click the text to type in it, the mouse an I-beam over it, and drag one of its two side handles (halfway down the text) to wrap the lines at that width: point text becomes a text box, its left edge where the text's was, the other side staying; double-click a handle for point text again, its left edge kept (undo steps Text Box Width and Point Text). Typing goes on the canvas with a caret and selection, as Blender's text edit mode: arrows (Ctrl by words), Home and End (Ctrl: the whole text), Up and Down, Shift selects, a drag or double-click selects, Backspace and Delete (Ctrl: words), Enter for a new line, Ctrl A, C, X and V, Ctrl B and Ctrl I for bold and italic (the selection, or all of it), Ctrl Z steps back through the typing; Esc (back to Transform Layer), Tab, a click away or another layer made active finishes, as one undo step (Edit Text). While typing, every key is the text's (Ctrl S still saves). The Properties editor's **Text** tab: the text in a box (edits keep each run's style where the text is unchanged), Font (a searchable list of the installed families, Weight, Italic, Size), Look (Fill, Outline, Material, colours, Line Width), Layout, and Convert: **To Vectors** (an ordinary vector layer of the letters, one way, as Blender's Convert to Curve), **To Letters** and **To Words** (a vector layer each, in a group in its place). With letters selected on the canvas, Font and Look change just them (the panel says so). New text: the Layers editor's + > Text. Python: oanim.ops.layer.new_text(text=, font=, size=, x=, y=), layer.text_body, layer.text_runs (dicts: text, font, weight, italic, size, has_fill, has_outline, fill, line, line_width, brush, material), layer.text_align, text_line_spacing, text_letter_spacing, text_word_spacing, text_shear, text_box_width, text_dont_auto_key, layer.text_bounds, oanim.ops.text.style_set(start=, end=, font=, size=, weight=, bold=, italic=, fill=, outline=), text.convert_to_vectors(split="NONE", "LETTERS" or "WORDS"), oanim.text_fonts(), oanim.text_font_from_postscript(name), oanim.wm.text_simulate(text) (typing, for tests).

**Point groups.** A layer's drawing has point groups, as Blender's objects have vertex groups: named sets of its points, each point in one with a weight (0 to 1), a point in as many as you like. They're selection sets now, and what modifiers will be limited to (a Bevel by group, its weights scaling each point's amount). The Vector tab's Point Groups panel is laid out as Blender's Vertex Groups: the list, each row the group's icon (a grid of points), its name and its padlock (click it to lock the group, so Assign and Remove leave it alone), the active group lit blue; click a row to make it the active group, double-click to rename it (a name already taken gets a number, "Group.001"); under the list, an arrow that opens its filter (a name search, and A-Z to show it in order of names) and a grip that drags the list taller or shorter. Beside the list: + (a new "Group"), - (removes the active one; its points stay), a menu (Sort by Name, Copy Point Group ("Group_copy", its points and weights), Remove from All Groups (the selected points, from every unlocked group), Delete All Unlocked Groups, Delete All Groups, Lock All, Unlock All) and the up and down arrows that move the active group in the list. Under it, two joined pairs on one row: Assign | Remove (put the selected points in the active group, with the Weight below, or take them out; greyed out with nothing selected or the group locked) and Select | Deselect (the group's points, added to or taken from the selection); then Weight, Blender's filled bar (click or drag to set it, Shift for fine), what Assign gives, kept while Open Animate runs. Blender's Auto Normalize is left out: it only evens out bone weights while weight painting. Groups keep their points by id, so they hold through edits: a point split in between two of a group's points is in it, weighted between theirs, as Blender's Subdivide does; a copy (Duplicate) is in its original's groups with its weights; a point deleted leaves its groups. A copy layer (reference) uses its original's points, so it has none of its own. Saved with the file. Python: layer.point_groups ([(name, {point index: weight}, locked)]), layer.active_point_group, oanim.ops.mesh.point_group_add (name=), _remove, _set (name=, active=1, lock=; index= or group= for one not active), _assign (weight=), _unassign, _select, _deselect, _move (direction=), _copy, _sort, _unassign_all, _remove_all (unlocked=1), _lock_all (lock=).

**Grids.** The Shape tool's Grid (beside Box and Circle) draws a grid in a vector layer: drag a box (Shift square, Alt from the centre, Ctrl snaps), its Columns and Rows (3 each at first, 1 to 32) in the header. The drag ends as Add Grid (mesh.primitive_grid_add): until anything else is done, the ViewportActionPanel changes its Columns, Rows, Location X and Y and Width and Height, making it again in place, as Blender's Add Mesh panel does, and the next grid starts with those cells; a Box or Circle ends the same way (Add Box, Add Circle, with Fill). It is ordinary drawing, points and curves: a node point where lines cross, a straight line along each row and one up each column sharing the nodes, all of them one outline shape named Grid (an outline-only shape whose lines meet three or more at a point is drawn line by line, each curve's run on its own, joined only where just two meet, so no stroke folds back on itself at a crossing), the new points selected; the layer keeps a note of which points are its nodes, row by row from the bottom. So every tool that edits points edits a grid (G, R, S, the Transform gizmo, handles, proportional editing, mirror, keys, bones, smart actions), and a layer can hold several grids among its other drawing. What a grid is for: a Warp modifier (to come) bends layers by it. Each cell bends what is in it as a Coons patch, the surface the four Bezier segments round it make: an unchanged grid changes nothing, a point on a grid line follows that line, a line curved with its handles curves what lies along it, and past the grid's edge places go on straight (along the patch's slope there); a place is found in the setup pose by the patches themselves, so a grid reshaped on frame 0 works too. A grid that loses a node is ordinary drawing from then on. Saved with the file. Python: layer.add_primitive("GRID", [corner, corner], columns=, rows=), layer.grids ([(name, columns, rows, [node point index])]), layer.grid_map(point, grid=0) (where the grid takes a place from its setup to now), oanim.ops.wm.tool_shape(shape="GRID", columns=, rows=).

**Extrude (E).** On the selected points: an open end's curve grows a new point past it (shapes covering the whole curve growing with it); any other point (a box's corner, a point inside a curve, a grid's crossing) starts a new open curve welded to it, as Moho's Add Point and Blender's Grease Pencil extrude do, closed curves included. The new points follow the mouse; E again from a new end keeps growing it. The end it grew from had no handle out (it led nowhere); now it takes one the way the curve came in, as long as its handle in, so the curve runs on smoothly there rather than turning. A branch's segment shows: in an outline-only shape through the point (a grid's), else as a new outline shape in the look of the shape there (its fill untouched). Python: layer.extrude_selected() (the first step, without the move), layer.shape_runs(shape) (a shape's pieces as drawn).

**Bones.** A skeleton is a tree of bones. Each bone has a rest position, angle and length plus animated position, angle and scale channels. Scale is X (across the bone: its thickness) and Y (along it: its length), as Blender's bone axes, and is for posing only: on frame 0, S resizes bones instead. Bones support IK with locks and angle limits, independent angle, maintain volume (squash and stretch), controlling bones (one bone's angle drives another's), bone dynamics (bones hang like weighted strands that swing, jiggle and stretch as the body moves), colour tags and a display shape. Points follow the bones by weights, as Blender's vertex groups: new points get automatic weights (nearer bones pull harder, a bone's strength widens its reach), and weights can be assigned or painted. A whole layer can be parented to one bone instead.

**Local armature viewport.** Every armature has two places its bones can live. **Viewport bones** sit in the scene: they move the character, deform artwork and show in the normal viewport. **Local bones** live in that armature's own local armature viewport, a separate canvas that belongs only to it, and never appear in the main viewport. This is where control bones go, such as smart-bone dials, sliders and switches, so they stop floating around the workspace. Both kinds belong to the same armature and key onto the same timeline. Bones are added and edited the same way in either place.

- **Control-only.** Local bones drive smart actions and can be controlling bones for viewport bones, but they cannot bind or deform artwork.
- **Separate trees.** A local bone can only be parented to another local bone, never to a viewport bone, and vice versa.
- **Helper artwork.** The local viewport can hold drawings that never render: labels, slider tracks, a face image to click on. Together with the local bones this makes a rig control board.
- **An editor type.** "Armature" is an editor you can put in any split area. It follows the selected armature and can also open as a floating window. Turning a dial there updates the character in the main viewport live.

**Animated channels.** One typed channel class covers numbers, 2D and 3D vectors, colours, booleans and strings. Channels can split into separate X/Y channels, be muted, and have keys selected for the timeline.

**Interpolation: Moho modes on the surface, Blender F-curves underneath.** Each key is stored like a Blender keyframe: a value, an in-handle and an out-handle, and a per-key interpolation mode. The modes are Moho's full set plus Blender's Back easing. Most modes compute their handles automatically, so they behave exactly as in Moho; in the graph editor, dragging a handle turns the key into a Bezier key, the way Blender's auto handles become free. Moho's per-key extras sit on top: a hold length, an interval for animating on 1s, 2s or 3s, a stagger flag and a colour tag. New keys get the new-key mode (saved with the preferences; Smooth to begin with), or, with Copy Previous Key on, the mode and settings of the key before them.

| Mode | What happens between this key and the next | Settings | Handles |
| --- | --- | --- | --- |
| Linear | Constant speed | — | None |
| Smooth | Eases through the key using its neighbours, clamped as Blender's auto-clamped handles: equal neighbouring keys hold still and the motion never overshoots a key | — | Automatic |
| Ease In/Out | Starts slowly and slows into the next key | Strength | Automatic |
| Ease In | Slows into the next key | Strength | Automatic |
| Ease Out | Starts slowly from this key | Strength | Automatic |
| Step | Holds the value, then jumps at the next key | — | None |
| Bezier | Custom curve | In and out angle and length per component | Free, aligned or vector, as in Blender |
| Back | Overshoots slightly, then settles (from Blender) | Overshoot amount | Formula |
| Bounce | Bounces into the next key | — | Formula |
| Elastic | Springs past the next key and settles | Amplitude (how far the first swing goes), period (how long each wobble is) | Formula |
| Noisy | Random jitter around the interpolated value | Amplitude, frequency | Formula |
| Cycle | Loops back to an earlier key | Frames back, or an absolute start frame | Copied from the cycled keys |
| Pose | Holds a value taken from an action | Which action pose | From the action |

All modes also take the hold length (frames to wait before moving) and the interval (1s, 2s, 3s). The Ease modes' Strength is one of Robert Penner's easing families, from Gentle (Sine) through Quad (the default), Cubic, Quart and Quint to Strong (Expo), plus Circ. Because keys share Blender's storage, drivers can later use the same curves.

**Picking a mode.** A key's interpolation is for the stretch arriving at it from the key before, as Moho's: how the motion gets to this pose (Step holds the key before, then jumps to this one; Ease In slows into this key). Its curve settings (Strength, Overshoot, Amplitude and Period, Amount and Wiggles) go with it; Hold, Animate On and Cycle are for after the key (Cycle loops after its key, so the stretch into a Cycle key is Smooth). The first key's mode does nothing. Files from before (format 3 and older, the Moho converter's too) had each key's curve for the stretch after it: opened, each moves onto the key after, so their motion stays the same. Smart actions play the stretch to their first key with that key's curve too, as the action shows when edited (before, always Smooth). The timeline's header has an Interpolation dropdown, as Moho's: with keys selected it sets their mode (it reads Mixed when they differ); with none selected it sets the mode new keys get. T over the timeline opens the same menu at the mouse, and right-clicking a key has it under Interpolation (the right-clicked keys join the selection first). Every item shows a small drawing of its curve, in groups: Smooth, Linear and Step; Ease (Ease In, Ease Out, Ease In/Out, and a Strength submenu); Bouncy (Back, Bounce, Elastic); Special (Noisy, Cycle). Bezier isn't offered: dragging a handle in the graph editor makes it. The menu also has Copy Previous Key, Copy Interpolation and Paste Interpolation (one key's mode and settings onto the selected keys, their values untouched), Use for New Keys, and Settings. The settings button beside the dropdown (or Settings in the menu) opens a panel with the selected segment's curve, drawn as progress from the key before (0) to this one (1), and the mode's own settings: Strength, Overshoot, Amplitude and Period, Amount and Wiggles, Loop Back; then Hold and Animate On (1s, 2s, 3s). A change goes to every selected key (a drag is one undo step); with no keys selected it changes what new keys get. A yes/no property's keys (visibility) stay Step whatever is chosen.

**Keys show their mode.** In the timeline a key's shape tells its family: a diamond for Smooth, a thin diamond for Linear, a square for Step, a circle for the Ease modes, a star for Back, Bounce and Elastic, and a hexagon for Noisy and Cycle; a frame where the keys of a row differ is a diamond. (A key whose handles were dragged gets a mark once the graph editor can drag them.)

**Stepped Preview.** A stairs button after the playback buttons (also Playback > Stepped Preview) plays everything as Step, holding each key until the next, to judge the timing of the poses while blocking. No key changes; turning it off brings the curves back.

**Actions.** An action is a named, alternative timeline that lives inside every channel of a layer; the regular timeline is the mainline. Actions belong to a bone layer and cover it and everything inside it. Editing an action switches the whole document into that action: its keys are swapped into the channels, layers outside the bone layer keep the mainline, and frame 0 stays the shared setup pose (editing it in an action changes the setup, and every bone pose with it). Actions can be inserted into the mainline as a copy or by reference, and blended.

**Smart bones.** A smart bone is an action with the same name as a bone. Inside the action, the bone's own angle is keyed over time, for example 0° at frame 0 and 90° at frame 24. On the mainline, the bone's current angle is looked up in that keyed range to find a matching action frame. Every other channel in the action is sampled at that frame, and its change from frame 0 is added on top. Visibility and Draw Order hold each key until the next, so they switch when the bone turns past a key's frame, never blending (a head turn that hides an eye at frame 24 hides it once the head turns past that frame's angle). Influences from several smart bones always add together. A second action named after the bone plus " 2" handles rotation in the other direction. It plays live while the smart bone is dragged, moving its bones and their points as it turns (bones the action moves without keys of their own included). On the setup frame (0) a smart bone plays nothing: turning it there sets its rest angle, as in Moho. **360 smart bones** (Moho 14.4's): a smart action whose bone is keyed exactly one whole turn from its setup (within a tenth of a degree, either way; Ctrl while turning finds it) goes round and round: the bone's turn counts modulo a turn, so turning on past the end starts it over and turning back past the setup plays it from the end (a dial for a 360 head turn). The timeline's action list marks it 360°; Python: layer.actions' "full_turn".

**Masking.** A layer's masks are **cards** whose steps name other layers (as Rive's and Figma's boolean stacks, After Effects' mask modes and Live2D's clipping); **Mask cards** below says how a card is built and how cards combine. Below, a row's shape settings are a step's, and Affects, End Lines at Edge, Ends, Reach and the viewport and render switches are its card's. Several layers in one row make one shape by the row's **Combine**: Union (all of them together, the default), Difference (the first layer's shape with the others cut out of it, so their order counts) or Intersection (only where all of them are), as Blender's Boolean; a group named means all of it, as one layer. Combine is three joined icon buttons (two overlapping rings, the part kept filled) just left of the layer chips, greyed out while the step has one layer; the summary joins the names by it ("inside head + hat", "inside head - mouth", "inside head & hat"), picking and End Lines at Edge follow it, and a file from before it opens as Union. A row takes its layers' shapes as drawn, before any masks of their own (those mask how a layer shows, not the shape it lends; only Clip to Below takes what its base shows); a file from before this lists, when opened, the layers whose masks named a layer with masks of its own. Each row has Invert (use what's outside its shape), Grow (pixels; negative shrinks; a pixel hides thin seams along the edge), Shape (which parts mask: As Drawn, fills and strokes as drawn; Fills Only, Moho's option, without strokes; Strokes Only, just the lines), Fill Every Shape (a checkbox: the inside of every shape masks, filled or not, an open one closed straight across, as Rive clips with a shape's path; greyed out with Strokes Only, and the summary then reads "on ring's lines"), Inside the Stroke (a checkbox, with Fills Only: the fills end at their lines' inner edge rather than down their middle, at any zoom, and wherever the line is drawn (a brushed line's turned or jittered dabs reach past its width, soft edges included), so an arm cut by a body shows over the body's whole outline where they join, as a copy of the body's fill on top would; each layer's lines trim only its own fills, so the lines inside a group (strands drawn over another layer's fill) don't cut the fills around them), Cuts (what of the masked layer the row masks: All; Fills, its fills only, as Toon Boom cuts colour art apart from line art; or Lines, its lines only, ended or sliced, its fills showing as if the row weren't there, so a head and an ear that cut each other's lines where they join keep both fills rather than leaving a hole where they overlap; picking and Clip to Below go by the fills; the summary adds "(its lines)" or "(its fills)"; a file with the older Lines Only opens as Lines), End Lines at Edge (a checkbox: the masked layer's lines end where they cross the row's shape, worked out along them before a brush lays its dabs, instead of being sliced there, with Ends: Brush (the line stops short of the edge with whole dabs, so nothing crosses it, with the brush's own taper and fade, and isn't sliced by the row's pixel clip; fills are masked as always, unless Cuts is Lines; with Cuts Fills it does nothing; the parts cut away show as faint dashed wires; a group's row ends the lines inside it; an Add row after one that ends lines ends them too, with that row's Ends, so it brings back the lines that row ended without End Lines at Edge on itself (the card says so under its checkbox); the summary adds "lines ending at head's edge"), Extend (None, Up, Down, Left, Right: the shape stretched to the edge of everything that way, in the mask layer's own directions, turning with it and its bone; several layers in a row can clip to one base, the first layer below them that doesn't clip; it applies after the rows. Its Exclude Strokes (under the checkbox) clips to the base's fills only, so shading stops inside the outline instead of covering it. A group's mask applies to everything in it. Masks don't depend on Draw Order or visibility: a hidden layer still masks (a mask shape is usually kept hidden), and one mask layer can mask many layers. A mask layer's own mask counts (its shape masks only where its rows show it). Copied together (Duplicate with both picked), a layer and its mask layer stay a pair: the copy is masked by the copy; a reference of a group masks itself with its own copies. Where they are set: the Layers editor shows a masked layer with just a mask symbol after its name, no text (orange, the colour masks are shown in everywhere; grey when all its rows are off): hovering it lists the rows and the result in words and outlines their layers in the viewport, and clicking it opens the Masking tab. A clipped layer is indented with an orange hook pointing down to its base. **Alt-dragging** a layer onto another adds a row of it there (Add; Shift: Subtract). **Alt-clicking** the line under a layer (the lower part of its row) clips it to the layer below, or releases it; **Ctrl Alt G** does the same for the picked layers. The Masking tab in Properties (next to Layer) starts with the result in words ("Shows: inside head, minus mouth, plus tongue"), a row to a line ("Shows:", then "everything but head", "plus tongue", "minus mouth and above"; **Mask cards.** Each card is a mask of its own, painted as Photoshop's layer masks are: it starts white (**Start With: Everything**, all shown) or black (**Nothing**), and its steps, read top to bottom, each paint their shape on it: **+ Shape** paints white (shows inside it), **- Shape** paints black (hides inside it), and a step's Invert paints the outside instead (- Shape with Invert keeps only what's inside). A step's shape is its layers combined (a chip each; Combine: Union, Difference or Intersection), with its own Shape (As Drawn, Fills Only, Strokes Only), Fill Every Shape, Inside the Stroke, Grow and Extend. The card says what of the layer it masks (Affects: All, Fills or Lines) and how it cuts lines: sliced by pixels, or, with End Lines at Edge, ended where they cross the edge of the card's whole shape (Ends Brush or Flat, Reach). The layer shows only where every card that masks that part shows it: cards multiply, so one can only hide, never bring back what another hid, and a card that leaves the fills alone doesn't touch them. So a head can have one card for the ear (Everything, - Shape Ear_L, + Shape of the outside of Ear_Line_Show, lines ending at its edge) and another for the neck (Nothing, + Shape Head_Base_X). A card's first step sets its Start With (+ Shape: Nothing; - Shape: Everything), and so does changing a lone step's mode; after that it changes only by hand. Clip to Below is a card of its own that starts from everything. In the Masking tab each card is a box: its header has the open arrow, a white or black swatch for its Start With, its name, a field edited in place as a modifier's (one undo step, "Rename Mask"; left empty it reads "Mask 1" by its place, and a named card's line in the summary starts with its name; hovering it shows the card in words), the viewport and render switches, a menu (Duplicate, Move to First, Move to Last, Delete), an x and a grip; inside, Affects with View first, Line Ends under it, then Start With (two joined buttons, a white and a black square), the steps (each a +/- pair of white and black squares, the Union / Difference / Intersection buttons, its layer chips with + and the eyedropper, an x that takes the step out (a card keeps one), Invert, and its Shape subpanel, folded), + Shape and - Shape (a new step, then click its layer). The summary at the top says each card on a line ("fills: everything but Head_Base_X", "lines: everything but Head_Base_X, plus Ear_Line_Show, lines ending at the edge"). Add Mask makes a card (Show Inside a Layer... starts it on black with + Shape, Hide Inside a Layer... on white with - Shape, then click the layer); Join Lines makes one card on each of the two layers. Rendering puts a layer's cards in up to three stencil levels by what they cut (fills and sliced lines, fills only, sliced lines only), each card worked out in a spare bit and kept only where the level already shows. Files from before cards turn each layer's rows into cards that show the same: the rows that masked its fills become a fills card and those that masked its lines a lines card (one card for both when they're the same rows), each starting where the layer's Start With, or its first row, said, the lines card ending lines if a row did; an Intersect row becomes - Shape with Invert flipped, a Difference row + Shape, and a row that was off a card of its own, off. Python: layer.masks (cards: name, start, cuts, end_lines, ends, reach, enabled, render and steps: mode ADD or SUBTRACT, invert, layers, combine UNION, DIFFERENCE or INTERSECTION, grow, shape, filled, inside_stroke, extend; a card's first step's keys are on it too), oanim.ops.mask.add (a new card; card= adds a step to one), mask.set (name=, start= and the card's settings; step= for a step's, combine= among them), mask.remove and mask.move (step= for a step), mask.duplicate; drivers: masks[i].start / cuts / end_lines / ends, masks[i].steps[j].mode / combine / invert / grow / shape / filled / inside_stroke / extend.

**Draw order.** Every layer has a keyable Draw Order: Normal (where the Layers editor puts it), In Front Of a layer, or Behind one. Its keys hold until the next key, as visibility's do. A rule can name any layer in the document, across groups and bone layers; a rule on a group moves the whole group; rules are settled outer groups first, then in the Layers editor's order. Masks name their layers, so a masked layer drawn in front of another layer is still clipped to its own mask. A group faded below full opacity is drawn as one image, so nothing inside it can leave it: a rule inside it that names a layer outside moves the whole faded group (the Draw Order row and the Layers editor say so). A rule naming a layer that is gone draws as Normal and shows "(missing)". On frame 0 the commands set the setup order; on any other frame they key it. **Ctrl ]** / **Ctrl [** (Bring Forward / Send Backward) move a layer past the next drawn layer that overlaps it, so every press shows (past one that doesn't only when none does); with **Shift**, Bring to Front / Send to Back. A step that lands where the Layers editor has it anyway goes back to Normal. **In Front Of... / Behind...** wait for a click on the other layer, in the viewport or the Layers editor: the layer pointed at is outlined and named, and the result shows before the click; Esc cancels. The Draw Order menu (right-click in the viewport with nothing selected, the points' right-click menu, and the Layers editor's right-click menu) has these and Normal, under "Now: In Front Of Torso". The Layer tab's Draw Order row has the mode, the layer (a list or the eyedropper) and the key button (in the viewport the eyedropper picks the group beside what moves, the outermost one holding the drawing clicked that doesn't hold the moving layer: a whole Eye group, not its pupil; Ctrl-click picks the drawing itself; the Layers editor picks the row clicked; Python: oanim.wm.draw_order_pick_target(hit, moving)). The Layers editor marks a layer drawn out of place on this frame with an arrow (up in front, down behind; red when its layer is gone): hovering says what it's drawn in front of or behind, clicking selects that layer. Its Order button lists the drawing layers in this frame's draw order instead of the tree, each with its group; dragging one onto another (upper half in front, lower half behind) sets its rule. In the timeline a Draw Order row (under the layer's Props, beside Opacity and Visibility; with Group by Kind, in its own Draw Order section) has square hold keys and, between them, a bar naming the rule in effect ("In Front Of Torso", or an arrow and the layer's name where the bar is short); hovering a bar outlines both layers in the viewport. Keyed Here lists it as "Draw Order: In Front Of Torso". Undo steps say what happened ("Hand In Front Of Torso"). Viewport clicks that pick a layer take the topmost as drawn. Python: layer.draw_order, oanim.data.draw_order (names as drawn, bottom first), oanim.ops.layer.draw_order_set(mode=, target=).

**Switch layers.** A Switch is a group that shows one of its children, or none (Moho's switch layers, Spine's slots, Rive's Solos, Harmony's drawing substitution; the research is in reports/Switch layer design.md and reports/Switch layer design review.md, one folder above the repo). Built in stages, all five done (2026-10-29); what's left is under Later.
- **What a key holds (stage 1, done).** The switch's Active channel holds the child's layer id, as Draw Order holds its target's, so renaming or reordering children never breaks a key (Moho keys by name and falls back to the top child; Harmony's rename trap; DragonBones and Rive by position). Files, Python and the UI show and take names. None (0) is a value of its own. Frame 0 holds the default child; a new switch's default is its top child, and a layer added to an empty switch becomes it. Keys only hold, as Visibility's do: no interpolation, no morphing between children (Moho's Interpolate Sub-Layers needs the same points in each child and breaks with smart bones). A key naming a child that is gone shows the default and says "(missing)"; Replace Keys With... points such keys at another child (stage 2). Copying or duplicating a switch keeps its keys pointing at the copied children.
- **Who wins (stage 1, done).** Choices never add (a child can't be added to another, the trap Blender's enum blending falls into); each frame has one winner, highest first: (1) a key made by hand on the timeline, after frame 0, holds until the next key; a **Rig** key hands the switch back to what is below it (Cartoon Animator's Release); (2) generated lip-sync keys (later, in their own layer, so running lip-sync again never touches hand keys); (3) smart actions: an action has a say once its bone has turned past one of its switch keys (a Rig key in it says nothing), and when several have a say the one listed first among the bone layer's actions wins; (4) the default (frame 0). Moho lets the smart bone win over hand keys with nothing on screen saying why ("the smartbone will override any manual keyframes you try to set"); here the hand wins and the timeline shows which source is in charge (stage 2). Visibility still adds its smart changes on top; moving it to this rule is a change of its own, not made yet.
- **Picking (stage 2, done).** One operator, layer.switch_set, picks a child and keys it at the current frame (on frame 0 it sets the default), following Auto Keying as any property does: with it off, a pick on a keyed switch shows until the frame changes and a pick on one not keyed yet is its value everywhere, nothing keyed (the status bar says so), and I or the key button keys it (I with one of its drawings active keys the switch's pick too); with Alt, hold=1, it picks for the whole hold the playhead is in instead, the key starting it (the default when that is frame 0) taking the child, no new key (Harmony 15.0.2 also made "this frame only" its default). It is reached from a dot before each child's type icon in the Layers editor (Rive's radio buttons: filled for the pick, a ring for the others, an orange ring for a child shown only for editing; the eye stays the viewport-only toggle), **[** and **]** (Previous and Next in Switch: the child above or below in the Layers editor, wrapping, from the one the viewport shows), and a **Switch: <name>** submenu in the Layers editor's and the viewport's right-click menus ("Now: Mouth A (keyed)", "(from the rig)" or "(the default)"; the children, the pick ticked; None; Rig; Replace Keys With). The switch's row in the Layers editor names its pick after its name. The timeline's Switch row draws a bar for each hold naming the child it shows, coloured by who decides there: teal for a key made by hand, orange for the rig (a Rig key, or the stretch from frame 0 when smart actions key the switch: "Rig, else Mouth E"), grey for the default, red for a child that is gone; its keys are the bars' edges, dragged as any keys. While one of a switch's drawings (or a layer inside one) is picked, the timeline lists the switch too once it is keyed, so a pick's key shows where it was made. Selecting a hidden child (or a layer inside one) in the Layers editor shows it in the viewport in place of the pick, to edit, without keying (Layer::edit_out), on the frame it was selected: once the frame changes (scrubbing, playing) the switch shows its picks again, though it stays active; renders and exports keep the pick, and a pick made while editing a child moves the active layer to the picked child. **Replace Keys With...** (layer.switch_replace_keys, from= a name or a gone child's id) points every key showing one child, frame 0's and actions' too, at another, and says how many. **Convert to Switch** (the Layers editor's right-click menu, layer.convert_to_switch) turns the active and picked groups into switches where they are, their children the drawings, the top one the default (name, place, masks and the rest kept; greyed out with no group picked). Python's layer.wrap_in_switch still puts the active and picked layers into a new switch, as Group With Selection does a group. Later: onion skins showing the other children (once onion skins exist), Shift [ and ] to jump between switch keys, and a thumbnail popup at the mouse, which comes with the asset shelf's thumbnails (stage 4).
- **Sub bone groups (stage 3, done).** A child of a switch can be a bone group with its own bones (a leg's thigh and shin, Spine's skin bones), hung from a bone of the bone group around it with Parent Bone (the hip). A bone group inside another is a **Sub Bone Group** (Layer tab, on by default; anim/bone_family.hh): while either is worked in, the bone groups worked in together (a family: out to the outermost through sub bone groups, then the sub bone groups shown inside) draw their bones together, and a click that misses the active bone group's bones picks a family bone under it, its bone group becoming the active one, so a character's bones all answer clicks. A sub bone group inside a switch belongs only while the switch shows it, so its bones come and go with its drawing; its keys are kept while hidden. Drawings follow only their nearest bone group (Moho's rule) and bones parent only within their bone group, so a drawing can't be bound to another child's bones and no bone parents across children: the warnings planned for those aren't needed. **Select Bones This Drawing Uses** (the Layers editor's right-click menu on a drawing in a bone group; armature.select_used_bones) selects the bones its points are weighted to and its Parent Bone, its bone group becoming active. **Match Pose from Previous Drawing** (the Switch menu; armature.match_pose_previous, not on frame 0) turns the active child's bones, and moves its roots, to lie in the picture as their counterparts in the drawing the switch's keys showed before this hold lie on this frame, and keys them whatever Auto Keying says: no pop at the swap (no surveyed tool has one). Later: IK targets on the shared skeleton for a child's bones (constraints name bones of their own bone group only, so this needs constraints that reach another bone group), and skipping a hidden child's dynamics.
- **Bone swaps (stage 3, done).** A bone can stand in for another in another child of the same switch (Bone::swap_layer, swap_bone: by id, so renames keep it): the Bone Relations panel's **Stands In For** (shown for bones of a switch's child), armature.bone_swap_set (a loop is refused), and **Auto-link Bones by Name** in the Switch menu (armature.swaps_auto_link: each child's bones stand in for the first child's of the same name). Bones that stand in for the same bone, along a chain of swaps, are counterparts. Swaps don't share poses: a front view's head tilt can be a smart bone while the side view's is the head bone's angle. A pick made while working in a child's bones selects their counterparts in the picked child, which becomes the bone group worked in; Match Pose lines counterparts up; the asset shelf offers a selected bone's switches. **Link All Channels** links a swap's channels two-way at factor 1 (stage 5). Python: a bone's stands_in_for ((bone layer, bone) or None), layer.sub_bone_group, layer.bone_family (the family's names, outermost first).
- **Two-way links (stage 5, done).** In the Driver window, a driver with one variable and an expression like var, -var, var * 0.5, 2 * var or var / 4 (or Average, Sum, Min or Max of its one variable), without Remap, can be ticked **2-Way Linked** (anim.driver_two_way; Data: Driver::two_way); others grey it out with the reason. It becomes **Factor** (never 0) and **Flip**, and the keys are stored once, the variable's: either side can be edited, an edit to the driven side going back into the variable (two_way_edits_back, before drivers work out; recording then keys the variable), as Synfig's linked values do (Blender's drivers are one-way; two pointing at each other loop). The change from rest is shared: driven = its rest + factor x (variable - its rest), so each side keeps its own rest (a bone's pose is a change from its setup already; another channel's rest is its frame-0 key, or what it was before it was first driven, which a driver remembers). Linking two animated properties asks which keys to keep and says how many go (keep=SOURCE or TARGET; the driven side's keys turned into the variable's); a two-number channel's keys go only when both its numbers are linked. Several links reading one property make a group (a dial, its front tilt and its side tilt); a property is in one group only (the side read can't be driven by another link, the driven side can't be read by one), and a smart bone can't be linked with something its own action keys. Unticking makes it a one-way driver again (var * factor); **Unlink** (anim.driver_unlink) takes it off, the driven side getting keys of its own that move it as the link did. Linked fields, either side, are teal (driven ones purple) and stay editable; their tooltip names the other side; their right-click menu has **Select Linked** (anim.driver_select_linked: its layer active, its bone selected) and Unlink; the driven side's timeline row shows the keys it shares. **Link All Channels** (the Relations panel beside Stands In For; armature.bone_link_all) links a bone's angle, position and scale at factor 1 with the bone it stands in for. Saved with the file; Python: a driver's two_way and factor (minus with Flip) in oanim.data.drivers. Later: Set Factor from Pose, and a side that IK or a constraint drives shown read-only.
- **Asset shelf (stage 4, done).** A view of its own, the **Asset Shelf** editor (in the editor-type menu and Window > New Area; the Layout workspace has one beside the timeline, Info to its right), grown from the Sculpt tool's brush shelf (Blender's asset shelf; src/editors/asset_shelf.cc). Its header has Context and All Switches, Pin ("Pinned": the rows stay whatever is selected), what it follows ("Mouth, in Head Front"), and search (Ctrl F), tile size and Preview, wrapping onto a second line when narrow. **Symmetrize layers.** The Layers editor's right-click menu has **Symmetrize + to -** and **Symmetrize - to +**: they make the other side of the active and picked layers, and of the layers in picked groups, mirrored across the document's vertical axis (x = 0); inside a bone layer, across the bone layer's own axis, the line bone Symmetrize uses. Partners pair by name, with the same left/right rule bones use (Ear_L and Ear_R, L arm and R arm, Left and Right; a trailing number kept). Each pair copies from whichever of the two sits on the side the command copies from (the middle of its drawing's box on the setup frame), whatever its name says, so either can be picked. A missing partner is made just above the source, in the same group, so a Clip to Below source and its copy clip to the same layer. An existing one is remade in place: it keeps its name, its place and its id, so masks naming it still do. A group named for a side goes as a whole: its layers flip their names where they have a side, keep their ids when they're remade, and are numbered when a name is taken ("Sleeve 1"). The copy's transform is the source's mirrored, and the layers inside it get their position's x and their rotation negated, so they move and turn the way the source's do. Drawings flip with their handles, widths, corners and detail points. Bone weights and Parent Bone move to the other side's bones (brow_L to brow_R). Every link naming a layer mirrored with it names that layer's copy (references, masks, Draw Order, bones' custom shapes, Limit to Shape constraints, a deform's shape, a Boolean's targets); one naming a sided layer outside names its other side (a row of Eye_L becomes Eye_R; Head_X stays). A reference stays a reference when its original is mirrored with it (it shows the copy, what it moved mirrored too) or has another side to show (Ear_L's reference shows Ear_R); any other is copied as a plain layer showing what it showed. A Mirror modifier's centre goes across with the drawing. A picked drawing named for neither side is symmetrized in place, as point Symmetrize does with all its points (each needs a partner across the layer's axis, or it's skipped). It works on the setup frame only. The copies rest in the setup pose: no point, handle or transform keys, so animate them after. It's one undo step ("Symmetrize + to -"), and the status bar lists what it made, remade, symmetrized and skipped (with why: "not on the + side", "3 points on the right, 0 on the left"). Python: oanim.ops.layer.symmetrize(direction="POSITIVE_TO_NEGATIVE" or "NEGATIVE_TO_POSITIVE").

**Links stay relative.** Duplicate (Shift D in the Layers editor), Symmetrize, Copy and Paste and a switch's Duplicate keep the links inside what they copy pointing inside it: a reference, mask row, Draw Order, bone custom shape, Limit to Shape constraint, deform's shape or Boolean target naming a layer copied with it names the copy (across several picked layers too), so a duplicated rig is self-contained; one naming a layer left behind keeps naming that layer (pasted into another file, the layer of that name there, else nothing).

**Copy and paste layers.** With the mouse over the Layers editor, **Ctrl C** copies the active layer and the picked ones, with everything in them, and **Ctrl V** pastes them above the active layer, in its group, into this file, another file or another running Open Animate (they travel on the system clipboard). They paste in their order, the one that was active when copied active again and the others picked; one undo step ("Paste 2 Layers"). Names already taken are numbered ("Ear_L 1"). Masks and Draw Order naming layers that came along name the pasted copies; ones naming layers left behind find this file's layer of the same name, and a mask row with none left goes. A shared material with the same name and look is reused, otherwise it is added (its name made unique). Pasted into a bone layer, Parent Bone and weights find its bones by name (a weight for a bone it doesn't have goes, so a point left with none gets automatic weights); pasted outside one, they let go. A reference whose original wasn't copied pastes as a plain layer showing what it showed; drivers wholly inside the copy come along. Python: oanim.ops.layer.copy(), oanim.ops.layer.paste().

**Grouping layers.** With the mouse over the Layers editor, **Ctrl G** (Group With Selection, also in its right-click menu) puts the active layer and the picked ones into a new group (a folder) where the active one was, in their order; a layer inside a picked group goes with that group. The new group becomes the active layer. One undo step; Python: oanim.ops.layer.group().

**Reference layers.** A reference layer is a live copy of another layer or group, in the same file or in another .oanim file. It shows the original's drawing, bones, smart bones and animation, and updates as the original changes. Open Animate copies Moho's rules:

- **Layer channels follow the original** (location, rotation, scale, opacity, animation and all) until you edit or key that channel on the reference. The channel is then changed on the copy: teal in the Transform panel and the timeline, where right-clicking it offers Reset to Original (its keys go too) and Push to Original.
- **Settings that are not keyable stay local** to each reference: masks, blend mode, label colour, lock and similar. This is what makes advanced masking work. A hidden reference of an animated body can be the mask of shading, textures or outlines anywhere, so they are clipped to the body's exact animated shape with no extra animation.
- **Referencing a group** references its whole tree; every child is itself a reference.
- **Making one:** **Alt D** in the Layers editor (Blender's Duplicate Linked; Shift D is an ordinary copy), the Layers editor's Ref button or right-click › Reference Layer: Duplicate as Reference, a reference of the active layer just above it.
- **A reference of a reference links to the original** (references never chain): Duplicate as Reference on a reference, or on a referenced group, makes a plain reference of the original layer (inside a group, of each original layer), without the copy's own changes. Files with a chain, made before this, open with it linked to the original.
- **Its own changes, each kept apart** (overrides, as Blender's library overrides, Unity's prefab overrides and Figma's instances keep theirs), found by the original's permanent point and shape ids so they stay on the right ones as the original changes. Everything not changed follows the original.
  - **Looks:** per shape and per setting (fill colour, line colour, line width, brush, fill and outline on), edited in the Shape tab's Shape panel as on any layer; a colour, line width or brush changed on a copy shows a revert button beside it in the Shape panel, and with its points locked the shape's Position is greyed out (point editing is locked); a shape of the original can be hidden on the reference only (from Python, layer.reference_hide_shape; listed under Changes, to reset); an edge can be hidden or shown on the reference only, with the Edge panel as on any layer, whether its points are locked or not (kept by the ids of the points at either end; Reset Looks brings back the original's); the Reference tab's **Recolor** has just Reset All Shape Styles and Push All Shape Styles (every colour, line width, brush and fill or outline changed on the copy, at once; hidden shapes stay hidden). Colour swaps (one colour of the original recoloured on every shape using it, the ones added later too) can still be made from Python (layer.reference_swap_color) and are listed under Changes.
  - **Points: Locked / Editable** (the Reference tab, or the lock in the viewport header beside Points / Edges / Strokes; locked by default, so points don't move by accident): moving a reference's points keeps offsets from the original's points, keyed like any edit; the offsets' keys add to the original's motion. **Follow Original's Animation** (under More, on by default); off, only the original's setup shape shows, with the reference's own keys. Handles turned or dragged are kept as offsets too (found by their point and the neighbour each points toward), added to the original's handles the same way. Widths and curve types stay the original's, and points can't be added or deleted (a message says so; Break Reference to change the drawing).
  - **Pose: Same as Original / Own Bones** (Same as Original by default): the reference shows the original's final shape, posed by its bones, smart bones and dynamics, wherever it sits (even outside the bone layer, as exact masks need); the top reference's own transform takes the place of the original's (and follows it until taken over), and everything inside a referenced group follows the original. With Own Bones, it binds to its own bone layer, starting with the original's weights by bone name (or automatic ones); its weights are its own, and Weight Paint changes them without touching the original's. Its Parent Bone is greyed out until it has Own Bones (posed Same as Original, it moves with the original's bones, so a parent bone set earlier waits).
  - **The Reference tab** (on references) holds everything about the link: "Copy of <original>" with Go to Original and how many changes it has, then a dropdown each: Pose, Points and Recolor (open), **Changes on This Copy** (folded to start with: grouped as Colors, Shapes, Points, Layer Animation and Bone Weights, each opening to its items, clicking one picks it in the viewport, with Reset and Push on each item and group) and More (Follow Original's Animation, Remove Unused Changes); Break Reference apart, with a warning. One vocabulary everywhere: **Reset** (back to the original) and **Push** (written into the original, so it and every copy get it; hiding and own weights stay the copy's).
  - **Changes show where they are:** a value the copy changed shows teal where it's edited (the Shape panel's settings, Transform, Opacity, Mean Position, the timeline's rows), as Blender shows overridden properties, and right-clicking it offers Reset to Original and Push to Original. The Layers editor marks a copy with changes with a teal dot, and while a copy is selected its original's row is outlined (or the folded group holding it). Something not allowed on a copy (deleting or adding its points, moving them while locked, changing widths or curve types) is undone, and a warning shows in the status bar's reports banner, as in Blender (also when a copy's selected points stay put while other layers' points move, as when editing from a bone layer); the same goes for the viewport's and rigging's other refusals (drawing away from the setup frame, changing the rig away from it, a bone hanging from its own child).
- **References to another file** show a warning when the original has changed. Updating offers Moho's options: add new layers, remove missing layers, replace mismatched bones, replace mismatched drawings.
- **Break reference** turns it into an ordinary layer that keeps what it shows, its offsets added to its points' keys so its animation stays as it was. A reference whose original is deleted does the same.
- **Better than Moho:** each channel stores its override flag explicitly, so a reference never silently gains keys or loses its link. Moho users report both problems ([forum thread](https://lostmarble.net/forum/viewtopic.php?t=37872)).

Sources on Moho's behaviour: the scripting API (`DuplicateLayer` by reference, `UpdateReferencedLayer`, `MohoLayerRefSyncOptions`) and [this forum thread](https://lostmarble.net/forum/viewtopic.php?t=34787).

**Tools.** A tool is an object with mouse, key and tablet callbacks, an overlay draw callback, an options bar, saved preferences, and checks that hide or grey it out by context. That maps directly onto our Python tool class.

## Feature spec

Version 1 covers 67 of the 98 features below: enough to draw, rig with smart bones, animate on a timeline and export frames. The rest are tiered Later or Maybe. Change any tier from its dropdown. "Community" means a feature that Moho users built as add-on scripts, so it becomes native here. Speed is a requirement throughout, not a feature: the viewport should play back at the document frame rate.

**World/Camera view toggle.** A toggle button in the viewport header switches the view between Camera and World; Numpad 0 does the same, as in Blender.

- **Camera:** you see exactly what renders, framed by the camera. The camera tools (track, zoom, roll, pan/tilt) move the scene camera.
- **World:** a free view you can orbit, pan and zoom around the whole scene. Layers show at their real depth, the camera appears as an outlined frame you can select and move, and imported meshes are visible from any angle.
- Each viewport remembers its own World position, so toggling back returns you to where you were. In a split layout, one viewport can stay in Camera while another is in World.

**The camera.** The canvas is infinite: the background goes on past the camera's frame. The camera is pinned at the top of the Layers editor; it isn't a layer, so it can't be moved in the list, hidden or locked. At the origin, zoom 1 and unrolled, its frame is where the page always was (2 units tall), so files from before cameras open unchanged.

- Picking it (its Layers row, or a click on its frame's border where nothing else is) makes the viewport look through it, as Blender's Lock Camera to View: the view fits the frame, drawn orange, and panning and zooming move and zoom the camera, one undo step per gesture. With it not picked the view moves freely (the wheel zooms at the mouse, middle drag pans, Ctrl + middle drag zooms about the middle of the view, as in Blender: up zooms in, down out), and Home frames the camera.
- The Passepartout (0 to 1) darkens the canvas outside the frame.
- While it is picked, Properties has a Camera tab: Position, Zoom and Roll, each with its key button, and Passepartout. Its keys show in the timeline under Camera, and under Selected while it is picked. The zoom's keys hold log2 of the zoom, so between keys it changes at a steady rate (from 1 to 4 it passes 2 halfway).
- Renders show exactly the frame. Render > Render Frame shows it in the Render Result window, with Save As...; right-clicking the image offers Copy Image (also Ctrl C over the window: to the clipboard as a PNG, keeping transparency for apps that read it, and as a bitmap for the rest) and Save As... (Python: oanim.wm.clipboard_set_image(rgba, width, height) puts any image there the same way). Python: oanim.data.camera (position, zoom, roll, passepartout, selected, keyframes(), to_frame()).
- File > Export: SVG (Current Frame)..., PDF (Current Frame)... and PDF (Frame Range, a Page a Frame)... write frames through the camera as vectors, at the document's size, each looking as Render Frame's picture does. One walk of the frame (src/io/vector_export.cc) makes a tree both files are written from: fills as their Bezier outlines; each line as one filled outline of what the renderer draws for it (its width at every point, joins and ends; the stroke's triangles merged by Clipper2), ended where End Lines at Edge ends it; a brushed line as a picture of its stamps, laid out as the renderer lays them and stamped on the CPU at twice the size; masks as luminance masks painted as the cards paint theirs (Start With, Add and Subtract, Invert, Union, Difference and Intersection, Grow and Shrink, Extend, Fills or Strokes Only, Inside the Stroke, Clip to Below; a card that masks only fills or only lines on just those); faded groups and see-through layers as groups with an opacity; media pictures shown in renders as pictures, greyed and tinted as drawn. The PDF (src/io/pdf_export.cc, written directly, streams compressed with miniz) has a page a frame (a pixel three quarters of a point) and every layer as a PDF layer (optional content) named and nested as in the Layers editor, so Acrobat or Illustrator can switch layers off and on; hidden layers and guides are in it too, switched off (a hidden mask layer still masks: masks are made apart from the layers shown); masks are soft masks, faded groups transparency groups; other frames are worked out on a copy of the document. Drawn by Chrome (SVG) and Windows' PDF renderer, the files match the app's PNG render but for anti-aliasing along edges: every render_check mask and fill case, brushed lines, a media picture, the Clay rigs and Rainbow Dash, no pixel more than 128 of 255 apart and at most 0.1% more than 64. Rainbow Dash: SVG 3 MB in 0.6 s; PDF 11 MB in 10 s (its 3,156 layers, 1,184 of them hidden). Python: oanim.ops.export.svg(filepath=..., width=, height=, transparent=), oanim.ops.export.pdf(filepath=..., frames="CURRENT" or "RANGE", frame_start=, frame_end=, width=, height=, transparent=).

**Number fields.** Every number field (Properties, headers, the ViewportActionPanel, Brush Settings, the timeline) works as Blender's: dragging it stays within its soft limits (from a value already past them it can come back but goes no further out); typing a value is held only to its hard limits, which are usually unlimited. A size or count can't be typed below its least, and a 0-1 fraction or a 0-100% amount can't be typed past its top; a property's own range (opacity's 0-1, shear's 89 degrees) is its hard limit, with an optional soft range for dragging. Sculpt's Strength is a factor bar filled across 0-1, dragged within it, typed as high as wanted, as Blender's (past 1, Grab and Push move further than the mouse, Pinch and Twist work harder, never past the centre, and Smooth takes more passes).

**The number field.** One widget (`src/editors/number_field.cc`) draws them all, ported from Blender's number buttons. Its label is on the left and its value on the right (the value alone is centred); a label without room loses its end. It has no arrows. A 0-1 value (opacity, weight, a strength, an option ranged 0-1) is a factor: a bar filled to where the value sits in its soft range. Dragging across, after a 3 pixel threshold, hides the cursor and reads only the mouse's motion (no screen edge to run into); letting go shows it again where it was pressed. A factor's full width is its whole soft range. Shift drags ten times finer, Ctrl snaps (by 0.1 under a range of about 2, else by 1; integers by 10), and Esc or a right click puts the value back. A click without dragging types into it. A typed sum (2*30+1, 1/3, parentheses, ^) is worked out, and Tab moves to the next field. Over a field, Ctrl+wheel steps it, minus negates it, Ctrl+C and Ctrl+V copy and paste its value, and Backspace resets it to its default where it has one. Dragging up or down first picks the fields passed over (X Y Z of a location), and then dragging across changes them all by the same amount. A value pen pressure can scale has a pen toggle joined to its right end: Draw's Width, Sculpt's Radius and Strength, and Weight Paint's Weight, Radius and Strength.

**Viewport toolbar.** A Blender-style toolbar runs down the left side of the viewport, in boxes always in this order, each its own panel: General (Select, Select Layer, Transform Layer, Cursor, Annotate), Drawing (Transform Points and Sculpt, then under a bar the frame-0 Draw, Shape and Split Curve), Rig (Transform Bones, then under a bar the frame-0 Weight Select and Weight Paint) and Text (Edit Text); hovering a box's edge names it. Select shows where there is something to pick: a drawing's points, a bone layer's bones, a group's drawings; not on a text or Media layer, which start with Transform Layer instead. Transform Layer (any layer, as Moho's): a box round what the active layer shows, in its own space (turning and scaling with it): drag inside to move the layer, the band round it (or the arcs at its corners) to turn it about its pivot (Shift: 45° steps), a handle to scale it, the opposite one staying put (Shift keeps proportions, Alt scales from the pivot), an edge between handles to shear it (its Shear X or Y: its Rotation stays, its Scale and Location keep the opposite edge still; Alt about the pivot, Shift in 15° steps); the pivot is the layer's origin until dragged (Ctrl snaps it to the box's corners, sides' middles and middle; a double-click puts it back), isn't saved, and G, R and S turn and scale about it too; Esc or right-click cancels; it sets the layer's Location, Rotation, Scale and Shear, keyed as any change (undo steps Move, Rotate, Scale and Shear Layer). While it is the tool, G, R and S move, turn and scale the active layer itself whatever it holds, and its points aren't shown (they stay selected); greyed out on a locked layer. With Show Grid Lines (its header checkbox, on at first) the viewport shows the active layer's own grid: lines at even steps of its own units through everything that places it (its transform, its groups', a bone it follows), so a layer squashed across has tall thin cells and a turned one a turned grid; one step both ways (from its average scale, in powers of 2, 24 to 48 pixels apart), so a squash shows; every 4th line stronger, and its own X axis (red) and Y axis (green) through its origin; it follows the box while it is dragged and hides with the overlays. Python: oanim.ops.wm.tool_transform_layer(), wm.tool_edit_text(), oanim.wm.layer_grid_lines(on). What shows goes by the active layer, as Moho's tools and Blender's modes do: a vector layer has General and Drawing, and inside a bone layer the Rig box's weight tools too; a bone layer has General, Drawing's Transform Points and Sculpt (which move what is drawn: making artwork isn't done there) and Rig's Transform Bones; a group has General and Drawing's Transform Points and Sculpt; a Media layer, General; a text layer, General and Text. A tool that can never work for the active layer doesn't show; one you can make work is greyed out, its tooltip and a click on it saying how: frame-0 tools on other frames ("press Tab"), and Transform Points and Sculpt on a bone layer or group with no drawings to edit ("turn on Editable in Bone Group" or Edit Descendants). Each kind of active layer (drawing, bone layer, group, Media, text, none) keeps the tool last used with it, as Blender's modes do: making that kind active again picks it again (the first time, and when it can't show: Select, else Transform Layer, else Select Layer). Taller than the viewport, the toolbar goes to two columns.

**Box gizmos.** Transform Points, Transform Bones and Transform Layer share one box, after Affinity's, Animate's and Harmony's: a line in the mode's colour over a dark edge (Transform blue, Distort orange, Warp purple), white square handles that fill with the colour under the mouse and can be grabbed from about twice their drawn size, short arcs just outside the corners where a drag turns it, and the pivot a ring with a crosshair. While dragging, the box goes with what it moves (turning, stretching and slanting), a grey dot marks where the pivot was, and a readout by the cursor gives the move, the angle, the scale (120% × 100%), the shear or the mode. A small selection still gets a box at least 48 pixels across, and a handle keeps the spot it was grabbed by. A double-click on the pivot puts it back in the middle. **Annotations and drawing guides.** Notes and visual aids drawn over the drawing, never part of it: they aren't layers (the Layers editor doesn't list them), are never rendered, aren't masked or moved by bones, look the same on every frame, and the drawing tools never snap to them or change because of them. Smooth is Blender's Grease Pencil Smooth on the resampled line: each dab blurs the samples with Blender's binomial kernel (gaussian_blur_1D, two iterations, ends kept, no keep shape), each moving strength x falloff of the way to its blurred place; as in Blender, a straight line stays straight while its points may slide along it, and a curve brushed long enough relaxes and shrinks. Surface Smooth moves the line toward its smoothed self: when a stroke starts, each curve is resampled at even steps along its length and noise-reduced by the Whittaker-Eilers smoother of the third order (Whittaker 1923; Eilers 2003: the line nearest the samples whose change of bend is least, one banded linear solve), which takes out wiggles shorter than its cutoff while an arc, a bend or a long wave keeps its shape; corners (a point not set smooth that is peaked or whose handles bend more than 25 degrees; a point set smooth never is, whatever its handles, so extruded points with handles of no length and sharp kinks between them are smoothed) and open ends stay put, and a loop is smoothed all round. Then each of the curve's own points goes where its place along the line went and each segment's handles are fitted to the smoothed line between its two points (their directions the smoothed line's), so the line with all its points traces the smoothed one; nothing is added or removed. While held, each point and its handles go strength x falloff x the frame's share of the way there, so the effect builds up and stops at the fit, never past it; an arc or a circle comes out as it was. While it is the brush, the fit shows as a pale ghost curve wherever it differs from the line by more than a pixel and a half (during a stroke the stroke's own fit, else the fit a stroke would start with now; after a Surface Smooth stroke it keeps that stroke's targets, since smoothing the smoothed line again lands in the same place; it is worked out again only after an edit, a stroke, undo or redo, or when the frame, the layers or the Lump Sensitivity change, and then only for the curves that changed (while Lump Sensitivity is being scrubbed only those the view shows, so it keeps up, and every editable curve once the scrubbing stops, so moving or zooming the view later finds them all fitted), never for moving or zooming the view, and a stroke starts from it rather than fitting again; it shows whether or not the mouse is over the view, so it follows Lump Sensitivity as that is scrubbed in the header), and the header shows its Lump Sensitivity, 0-1 (a slider, default 0.25, dragged within 0.001-1, typed as high as wanted or down to 0, which takes out nothing) for how long a wiggle along the line it takes out: 1 is a quarter of the canvas's height, so wiggles up to about that long go however tall they are, while longer waves stay; the result changes smoothly as it is scrubbed; neither the file's resolution, the brush's size nor the zoom changes it. The ghost follows it as it changes. Python: surface_sensitivity in oanim.wm.set_sculpt, sensitivity= on sculpt.stroke. Surface Smooth has no key. **Materials.** Shared looks for shapes, as Blender's materials (Moho's library styles, Illustrator's global swatches). A shape has its own look, or is linked to one material, which then sets everything about its look: fill colour, line colour, line width and brush (Fill and Outline on/off and the points' widths stay the shape's). Changing a linked shape's look in the Material panel (its Brush section too, or Python) changes the material, and every shape using it changes with it. Which you're editing is plain to see: the panel's header, even folded, says "Material: Skin (shared by 12 shapes)", or "Material: Own look"; while one of a shared material's fields is under the mouse or being changed, every shape using the material is outlined in the viewport and the header says "editing Skin changes 12 shapes". Linked shapes carry a white corner mark (Illustrator's global swatch triangle) on their swatch in the Shapes list, on the browse button and in the materials list. The Shape tab's Material panel (folding, under the Shape panel, which keeps Name, Position and Fill / Outline) holds the look: its first row is Blender's data-block selector, then Fill Color, Line Color, Line Width and the Brush row (below). **Line weight at any zoom.** A line keeps its true weight however far the view (or a render) is zoomed out: one thinner than a pixel is drawn a pixel wide and as much fainter, rather than every hairline looking a pixel thick; a brushed line's stamps fade so that, overlapping, they come to its thinness. Masks still take hairlines a pixel wide.

**Brushes.** Open Animate copies Moho's stamp brushes: a line can be drawn as a row of image stamps instead of a solid stroke. A brush is part of a line's style, so shared styles share their brush. The stamps stick to the artwork: they are laid out along the line as drawn on the setup frame, each at a place on one of its segments, and kept at that place as points move and bones bend the line, so they stretch and squash with it instead of sliding along it (Moho's slide as a curve stretches; Toon Boom's textured lines are fixed to the line like this). A segment stretched past 1.5 times its length fades in stamps halfway between its own (and again at 3 times, ...), and one squashed below three quarters fades out every other one, so a line never breaks into dots or clots, after Bénard et al.'s self-similar line textures. Brush Settings' When Stretched picks whether those stamps fade (the default) or pop in and out whole. The layout doesn't depend on the zoom, so the viewport and renders agree.

- **Brush row**, in the Material panel: a preview stroke in the line colour, named in its corner by the preset it matches ("Ink"), or "Custom" when it matches none (edited since, or never one), or "Solid line", with Blender's **preset button** (three sliders, as tall as the preview) at its left. The button opens Brush Settings on its settings; clicking the preview opens it on the presets (the Brushes tab). In the preview's bottom right, the **brush eyedropper**: click it, then a stroke in the viewport (anywhere on it as drawn, its width included), and the selected shapes get that shape's whole brush, as one undo step (Esc, right-click or a click off any shape stops it; the cue at the mouse says so). The Draw tool's header has a button for the brush new strokes get, opening it on the tool.
- **Brush Settings window**, after Photoshop's Brush Settings and Brushes panels. It floats over the app and doesn't block it, so the viewport shows every change as it's made, and says what it edits ("3 selected shapes", "The Draw tool's brush"). It follows the selection: it shows the active shape's brush, and a change goes to every selected shape as just that setting, so they keep their other differences. Two tabs:
  - **Brush Settings:** Photoshop's sections down the left, each with its switch (a section switched off keeps its values): Brush Tip Shape, Shape Dynamics, Scattering, Color Dynamics, Transfer, Line Boil. The chosen one's settings are on the right and a large preview stroke runs along the bottom. - **Brush presets:** a shape plus every setting, saved by name (as Krita keeps presets apart from brush tips). **Detail levels (multiresolution shapes).** A shape can be edited with fewer or more points without losing its look, as Blender's Multiresolution modifier and ZBrush's subdivision levels do for meshes and Finkelstein and Salesin's multiresolution curves do for lines: the overall sweep is edited at a low level while the fine detail rides along.

- **Levels.** Level 0 is the shape's own points (what bones, weights and Parent Bone act on). A detail point at level k lives on one segment of level k-1: where it sits along the segment and how far it stands off it, measured along and across the segment and scaled with its length (Stretch: a segment twice as long has its detail twice as wide and twice as tall, so scaling a shape scales its detail and a shrinking segment never makes spikes). Its handles are kept the same way. Moving, bending or stretching the coarse curve carries the detail with it. On a higher level, though, the detail points that level shows are points of their own: moving a coarser point there leaves them where they are, and only the finer detail hidden above the level rides; keyed moves of the coarse points still carry every level as they play. Bones move detail points by their own weights, which they get from their neighbours as any new point does. A parent's handle facing finer detail is shown and edited as its handle at its own level (its coarse handle, longer than the piece it shapes); lines draw with the handles the splits give.
- **Per shape.** Each shape keeps its own level, saved with it; changing it is an undo step (Detail Level). Each shape's curves show their points up to its level (base points drawn bigger, the level's own at normal size, finer ones hidden); a curve shared by shapes at different levels uses the higher one. The full detail always shows and renders. Points hidden by stepping down are deselected.
- **Adding detail: the knife only.** Nothing subdivides on its own: the Split Curve tool (K) adds every detail point. At a level above a shape's top level (stepping one past it opens an empty level, with the hint "Knife (K) adds detail points at this level") the knife adds a detail point at the shape's level, on that segment only; at level 0 it adds a base point as it always has.
- **Where it is set.** The viewport header shows Detail ‹ 1 / 3 › (arrows, drag or type) while a shape is selected; with several selected at different levels it shows a dash, and setting it puts them all on that level. Ctrl+0 to Ctrl+4 set the selected shapes' level (with none selected the status bar says "Select a shape first"); Alt+Page Up and Alt+Page Down step it. The viewport's info text adds the active shape's level (Detail 1/3). The Shape tab's Shape panel has a Detail section: the same Level field, the shape's levels and detail points (Levels 3 · 14 detail points), Delete Higher (the detail above the current level), Apply Detail (flatten it into base points) and Rebuild Levels (turn a dense drawing, such as a Moho import, into a base plus detail: its detail flattened first, each point within the Tolerance of the curve its neighbours make without it becomes detail; when none can, nothing changes), each on the selected shapes and undoable. Apply Detail and Rebuild Levels work on the setup frame; keys they can't keep (a detail point's offsets) are removed, and the status bar says so. Python: layer.detail, oanim.ops.mesh.detail_level_set(level= or delta=), detail_delete_higher, detail_apply, detail_rebuild(tolerance=); layer.split_segment adds detail at the curve's level.
- **Wires** show each curve at its shape's level: through the points shown, with their handles as they are at that level, so the wire is what you bend; the stroke under it draws all of its detail. Clicking a line in Edges or Strokes mode picks that same curve.
- **Animation.** Detail points key like any point, relative to the setup pose and in their segment's frame, so animating the base points carries the detail and a lower level is the place for big moves.
- **Smooth to Lower Level** (right-click with detail points selected) moves them, or handles of detail points picked on their own, onto the curve of the level below, so they keep none of their own offset; the ViewportActionPanel's Influence (0 to 1) sets how far. Away from frame 0 it poses them (auto-key keys it). Python: oanim.ops.mesh.detail_smooth(influence=).
- **Move to Higher Level** (right-click with points selected) moves them one detail level up, keeping the curve's look (their places along the segment between the coarser points around them worked out anew), so they ride those points and hide below their level. An open curve's ends, points on more than one curve and points at the top level stay (the status bar says how many); a closed curve keeps at least two coarser points. Setup frame only; their keys go (as Rebuild Levels'). Python: oanim.ops.mesh.detail_raise().
- **Move to Lower Level** (right-click with detail points selected) moves them one detail level down, keeping the curve's look: from level 1 they become base points. The finer detail around them takes them for a parent (its places along the new segments worked out anew), so it rides them from then on. Base points can't go lower (the status bar says so). Setup frame only; their keys go. Python: oanim.ops.mesh.detail_lower().
- **Editing the base.** Deleting a base point joins its two segments and their detail moves onto the joined one (the status bar says so: "Merged the detail of 2 segments"); splitting a segment at level 0 gives each detail point to the half it is on. Symmetrize, mirror editing, references and smart actions treat detail points as points (each has an id).

**Media layers.** A Media layer shows an image, a numbered image sequence, a video or a sound, read with Windows' own decoders (WIC for images, Media Foundation for video and sound: what plays in Photos and Media Player opens here).

- **Adding one takes a drop, no dialog.** Drop a file on the viewport and it becomes a Media layer above the active one, starting on frame 1; dropped on the timeline, it starts on the frame it lands on; dropped on a Media layer's clips row, it joins that layer as a clip there instead (picked, over what was there). While the file is still being dragged, it shows live where it would land: in the timeline a dashed bar as long as the clip it would make, at the frame under the mouse ("Add clip walk.mp4: frames 81 to 128" on a clips row, "New Media layer ..." elsewhere), and over the viewport the outline of its picture fitted to the camera's frame with what it is (Open Animate's own drop target reads the files as the drag enters; SDL's names them only on the drop). File > Import > Media and the Layers editor's + > Media... do the same with a file dialog. A numbered image ("walk_0001.png" with siblings) comes in as an image sequence. Named after the file. Its options then show in the ViewportActionPanel: Start Frame, Fit, Opacity, Guide; the Properties editor turns to its Media tab.

Clicking in the viewport never picks it, so drawing over it is safe; it is picked in the Layers editor or the timeline, and the Select tool says to add a vector layer above it to draw. **Multi-layer editing.** Select several vector layers in the Layers panel (Ctrl-click one at a time, Shift-click a run of them) and the point tools work on all of them at once.

- Points of every selected layer are shown and selectable; the active layer is highlighted, the others drawn slightly dimmer.
- Box and lasso select pick points across all selected layers in one drag.
- Move, rotate and scale (including G, R, S) transform every selected point together around one shared pivot. Each point still moves correctly inside its own layer, even when the layers have different transforms or bones.
- Curvature, line width, delete, and the sculpt brushes also act on all selected layers.
- On an animated frame, keys are set in each layer that changed. The whole edit is one undo step.
- **Edit Descendants** (a group's checkbox in the Layer tab): while the group is picked or active, every drawing inside it, however deep, is edited as if picked too (a hidden or locked one, or one inside a hidden group, stays out). On for groups, off for bone groups (whose drawings come with their bone collections); converting one to the other sets it to match. **Armature modifier.** The bones moving a drawing are a modifier too: every layer inside a bone layer has one Armature modifier, added and removed with the bone layer and never deleted by hand. Its place in the stack decides what the bones move: a Mirror modifier above it mirrors the setup drawing, so each half follows its own side's bones (a point bound or weighted to `arm_L` mirrors to `arm_R`); below it, the posed drawing is mirrored. The stack runs top to bottom, each modifier working on what the ones above it made, and Add Modifier puts a new one at the bottom, as Blender does (drag it above the Armature modifier to work on the setup drawing).

**Boolean modifier.** Joins a layer's shapes and other layers' into one outline, as Moho's Liquid Shapes join shapes, but across layers, so each part keeps its own bones and draw order. Add it from Add Modifier > Boolean on the layer that owns the look. Its settings: **Shapes** (which of the layer's own shapes merge: All shapes, every one that goes all the way round, or the ones ticked); **Layers** (the layers merged in, a row each: the layer, a dropdown as Parent Bone's with a search field on top (focused as it opens; any part of the name, any case; Enter takes the first left), picking another layer to merge in its place; its shapes, a dropdown of checkboxes with its own search; an eyedropper; and x to stop merging it; then an Add Layer... row, the same dropdown and eyedropper. The eyedropper takes a shape clicked in the viewport and its layer together: on Add Layer... it adds them, on a layer's row it puts them in that layer's place, and the shape clicked is what it takes: added to a layer's picks, or picked alone on a layer taking all its shapes. While it's on, the cue at the mouse names what a click would take, "Layer | Shape" (Ear_L | S7), as every shape eyedropper does. It looks past the merging layer itself, which may be drawn over what it merges, and a shape not going all the way round can't merge, so it waits for another click); **Operation** (Union: one outline round them all; Subtract: the others cut away, the outline running on along the cut; Intersect: only where they overlap); **Smoothing** (a radius in the layer's units, keyable and drivable: it rounds the corners where the outlines meet, and only there, so the shapes' own drawn corners stay sharp; 0 keeps the joins sharp); **Corners Only** (with Union: the layer's shapes just grow the rounded corners where they meet the others, taking nothing from them); and **Apply** (the header menu's Apply, or Ctrl A over it; on Setup, frame 0: the merged outline becomes the layer's drawing, the shapes it took leave their layers, and the modifier goes). The result takes the first own shape's place in the layer and its look (fill, line, brush and material); the line keeps the width it had where each part came from, and a brushed line lays its stamps along the merged outline as it is. The other layers are merged as they're posed (their bones and modifiers first), and a Boolean runs at its place in the stack, as every modifier does: a Bevel below it bevels the joined outline, above it only the layer's own shapes. **What it takes:** what its own shape draws. A layer that draws fill and line takes the merged shapes whole, so they stop drawing on their own layers and nothing is drawn twice; an outline-only layer takes just their lines, their fills still drawing on their own layers; a fill-only one just their fills. The rest of a merged-in layer (an ear's inner line, say) still draws on that layer, at its own place in the stack, and clicking a merged part still picks its own layer. So a rig that draws its lines on their own layers (a head's fill and a Head_Outline copy) gets an ear joined with a Boolean on the outline layer (Ear_L's base shape, with Smoothing) and a Corners Only Boolean on the fill layer with the same Smoothing, so the rounded corners are filled too. Hidden, a layer isn't joined (Union); as a cutter (Subtract, Intersect) it cuts hidden or not, as a mask shape does, and isn't drawn. Two layers merged together don't mask each other: their mask steps naming each other (a Join Lines pair) are left out, so lines aren't cut where the outline now runs. Two layers merging each other stop there. Merged geometry is worked out with Clipper2 (polygon booleans and offsets: grown then shrunk by the radius near where the outlines cross, which rounds those corners) and turned back into curves, smooth where they bend gently and sharp where they turn hard. Python: oanim.ops.object.modifier_add(type="BOOLEAN", targets="Ear_L"), object.modifier_boolean_set(index=, targets=, operation=, smoothing=, corners_only=, shapes=, target=, target_shapes=, and the eyedropper's pick= with pick_shape= and replace=), object.modifier_apply(index=); layer.modifiers gives a Boolean's targets, target_shapes, shapes, operation, smoothing and corners_only; layer.evaluated() says of each shape what another layer's Boolean draws of it ("ALL", "FILL", "LINE"). Drivers and keys: modifiers[i].smoothing. It was called Merge at first: files saying so open with a Boolean (a default name "Merge" becomes "Boolean").

**Bevel modifier.** Cuts a drawing's corners off and rounds them, Blender's Bevel modifier in Vertices mode, for curves. Add it from Add Modifier > Bevel; it goes at the bottom of the stack, so it bevels the posed drawing and a corner keeps its size however it's bent (dragged above the Armature modifier, the bones bend the bevelled drawing). Its panel has Blender's rows: **Width Type** (what Amount measures: Offset, how far along each side from the corner the cut starts; Width, how long the cut is; Depth, how far the cut is from the corner; Percent, how much of each side it takes), **Amount** (keyable and drivable, with its key button), **Limit Method** (None: every point between two segments; Angle: only the corners where the outline turns more than the **Angle**, 30 degrees by default, measured on the curve itself, handles and all, so a smooth point is never cut; Point Group: only the points of the **Point Group** picked from a dropdown with a search field, each cut by its weight, so a point at 0.5 gets half the cut), then two folded subpanels: **Profile** (its Shape, Blender's filled bar: 0.5 round, a circle's arc; 0.25 straight, a chamfer; 1 square, almost the corner again; below 0.25 scooped inward, at 0 a circle's arc turned in) and **Geometry** (Clamp Overlap, on by default: two cuts on one segment take at most half of it each, so they never cross). Blender's Vertices / Edges switch, Segments and Shading are left out: there are no edges to bevel, one Bezier segment already makes a smooth round, and shading is 3D's. Each cut corner becomes two points, one on each side, joined by a new segment that every shape running through the corner takes in; the curve either side keeps its shape exactly, its segments trimmed (de Casteljau), not refitted. Line ends and points where curves weld aren't cut. The first point keeps the corner's id, keys and bone weights, the second is a copy of it, so the bones still move them. Brushed lines lay their stamps along the bevelled setup shape. Apply (the header menu's, or Ctrl A; on Setup) makes the cuts the drawing's own points. **Resample modifier** (called Subdivide at first). Adds points between the drawing's own (which stay as they are, keys, weights and all), evenly in each segment, before the bones bend it, so one long segment bends along a bone chain instead of only at its two points: bendier animation without more points to animate (Blender's Grease Pencil Subdivide, for curves). Add it from Add Modifier > Resample; it goes above the Armature modifier by itself (below it, it says to drag it up). The split is exact, so at rest the drawing looks the same; corners stay corners and the new points are smooth. **Mode** (two joined buttons, as the bone Shape selector): Per Segment (default) splits every segment into Pieces (4), so it always adds points and how many is easy to tell; By Length puts a point at least every Spacing (0.05) along each segment, cut evenly along it as it is in the setup pose, so the pieces and where they sit stay the same on every frame. Under them it says how many points it adds ("Adds 240 points"), and when it adds none, why, in orange ("every segment is shorter than Spacing", "Pieces is 1", no segment touching its point group); Show Points' tooltip gives the same count. The rest is folded under **More**: **Weights** (the same kind of buttons): Blend (default) mixes each new point's two end points' weights by how far along it is, a smooth rubber-hose bend; From Bones weights it from the nearest bones, so a segment can bend at a joint between its points. **Preserve Volume** (on by default) moves the new points by blending the bones' turns as rigid motions (dual complex numbers, Blender's Preserve Volume) rather than their matrices, so the line doesn't pinch where bones turn far apart; the drawing's own points move as before. Render (By Length only): a finer Spacing for the final render, Same by default. Handles the curve works out stay that way in spirit: Resample stores them, and the bones turn and stretch them with the curve around the point rather than rigidly with it. Where neighbouring bones turn very differently and point keys keep a shape right (stiff hair spikes), the blended points bend through the difference: there Resample changes the existing animation's look, and a Point Group or no Resample suits better. Max Pieces (64) caps any segment; Point Group limits it to the segments touching a group's points. Apply (on Setup, on a drawing whose points aren't animated) makes the new points real. Saved with the project; files and scripts saying SUBDIVIDE still work (a default name "Subdivide" opens as "Resample"); Python: object.modifier_add(type="RESAMPLE"), layer.modifier_set(i, split="LENGTH"|"COUNT", spacing=, render_spacing=, pieces=, max_pieces=, weights="BLEND"|"BONES", preserve_volume=, group=).

**Deform modifiers: Curve, Cage and Mesh Deform.** A shape on any other drawing layer bends the layer (Moho's Smart Warp, Live2D's warp deformers, Blender's Curve, Mesh Deform and Lattice), picked in the modifier as a Layer and one of its Shapes, or with the eyedropper at the end of the Shape row (as Boolean's: click the shape in the viewport and its layer comes with it, looking past this layer; one this deform doesn't take still goes in, and the modifier says which does; a layer clicked in the Layers editor goes in with the first of its shapes this deform takes, else its only one); Add Modifier lists the three under Deform, each taking its own shapes: **Curve Deform** an open line, **Cage Deform** one closed shape, **Mesh Deform** a grid, a mesh of cells drawn by hand (or a closed four-sided shape, as one grid cell), or lines (an open line, or lines left dangling from a mesh). Their Shape lists offer only the shapes they take (the others greyed, naming the deform that takes them); a shape that stops fitting (joined into cells, closed, opened) makes the modifier say which deform it needs, with a Switch button, and the header menu's Change Type turns one into another, keeping its settings and painted weights. Files from when there was one Vector Deform open with each as the deform its shape fits (a line Curve, a single closed shape Cage, cells Mesh). They share everything below. What each does with its shape: a **Grid** (the Shape tool's) bends each cell's contents as its Coons patch, so a grid line curved with its handles curves what lies along it; each side's pull fades out smoothly toward the side opposite (3x² − 2x³, not in a straight line: half way across it is half, by the far side nothing and with no slope), so moving one side or handle barely moves what lies by the others; a closed shape is a **Cage**, what is in it following its outline as drawn, curves and all, so pulling a handle bends the inside, by Cage Deform's **Method** (a dropdown): **Mean Value** (the default: mean value coordinates measured against the outline; smooth, and a point on the outline stays on it, but the inside squashes along a side that bulges out or stretches), **Rigid** (as rigid as possible, Sorkine and Alexa's, as Photoshop's Puppet Warp: a lattice of square cells over the cage, each node keeping how it sits with its four neighbours, turned as they turn together, with the outline held firmly where it goes; how far that moves the inside from Mean Value is laid on the lattice and read back by a cubic B-spline, so it is smooth; the inside keeps its shape as far as it can, squashing least, and the outline stays on the cage, to within about a third of a per cent of its size; for art drawn along the cage's edge; each round of its solve is exact, by the Cholesky factor of the lattice's system, worked out once with the lattice (it is the same every round and every frame), so nothing wobbles as the cage moves) or **Envelope** (as Toon Boom Harmony's envelopes, which bend a drawing's outlines while keeping its line widths: every point goes where Rigid puts it, then each side of the cage (the outline from one of its points to the next) sets the point's distance from that side back to what it was at rest (measured from the side's nearest place to the point; where two parts of a curved side are nearly as near, within a fiftieth of its length, the two blended, so that place never jumps from one to the other as the side moves), so a line or band along the outline keeps its width, inside the cage and past it, and art hugs the cage however a side bends, stretches or is pushed in; a side sets distances only, never where a point slides along it, so two sides meeting at a corner never pull a point two ways (in Harmony's own each side takes the part of the drawing nearest it and art tears where two meet); a side's say is full at it and less further off, as r / (r + distance) with r the cage's size, so the distance a point ends at always grows with the distance it had and nothing folds over, however hard a side pushes in, and deep inside the cage as a whole leads; the sides near a place share it by nearness, **Blend** (0 to 1, 0.5 by default) saying how evenly: 0, the nearest leads sharply (as the cube of how near it is), 1, gently (as how near it is), sharper than the cube folding a corner that closes up; a band a tenth as wide as the cage along a side pushed in to the middle keeps 88% of its width or more, where Mean Value keeps 6%; about Rigid's work); with Mean Value and Rigid, what lies past the outline keeps its distance from it: each side carries it from where its place on the side goes, turned as the side turns there but not stretched, the sides blended by nearness (inverse fourth power), so a band drawn along the outside stays as wide however a side bends in or out (mean value coordinates past the outline would squeeze it); an open shape is a **Line**, what lies along it keeping its distance along it (measured along the line, as Blender's Curve modifier and skeletal strokes do) and its offset from it; **Stretch** (on) spreads it end to end as the line grows (Illustrator's Art Brush), off it keeps its length and slides along; on the inside of a tight bend, offsets past half the bend's radius ease toward it so nothing folds over. Its place along and across the line is worked out on the line at rest and now alike (the same frame and bend easing), and how far a point is from where that puts it at rest is carried along in the line's frame, so a line that hasn't moved moves nothing and one moved or turned whole carries everything exactly; a point far from the line takes the way it runs over a stretch about as long as the point is far, so it doesn't hitch as the line's samples turn by small corners; the line is followed at 64 pieces a segment (a cage at 16); where the line winds so that a point has a near place on more than one part of it, it is carried from each and they are blended by nearness (the eighth power), as a wire's points are, so the drawing doesn't tear where the nearest part changes. A **network** drawn by hand (lines joined into cells, as Extrude and Make Segment make them) bends each cell's contents by that cell: a four-sided cell as a grid's cell does (so a hand-made grid is a **Grid**, bending as the Shape tool's would), any other as a small cage (**Mesh**); cells sharing a side follow it alike, so they join without a seam; a point on a four-sided cell's curved side counts as in the cell (judged by the side itself, not the polygon of its samples), a point on a side, and a handle along it, follows the bent side itself at the same place along it (exact, also at a corner where two sides run on in line, where the patch's own directions are parallel), and other handles there turn by the patch's own derivatives, ; near a corner where the two sides run on in line (a smooth shape cut into four sides) the patch's own directions are nearly parallel and it would kink what lies there, so it eases over to the cell as a cage (mean value coordinates on its outline) by how square those directions are; so a drawing that is a copy of the warp shape bends into exactly the bent shape, handles and all (Python: layer.evaluated_handles(curve, shown=False) reads the handles after the modifiers, shown=True as the viewport shows them; layer.evaluated_outline(shape, steps=16) a shape's outline as the evaluated drawing draws it). A Mesh Deform's lines are **wires**, like bendy bones (an open line alone is a **Wire**): each point is pinned on frame 0 to its nearest place on the line as a whole (that segment, that far along it) and its offset from there, and goes where that place goes, turned as the line turns there, so nothing slides along the line (Curve Deform, by contrast, lays what lies along a line out along it by distance); where a line folds back or winds, so that a point has a near place on more than one branch, the pins at each blend by nearness, so nothing jumps between branches; a segment of no length at rest (points stacked on one another, as a piece copied from a fill's outline can have) is left out, having no way to turn anything with; past an end it rides that end; points far from the line follow it smoothed over a stretch as long as they are far (the line carrying on straight past its ends), so a sharp bend is a gentle one to them and offsets never cross (the line at rest smoothed alike, how far a point is from where that puts it carried in the line's frame: a wire that hasn't moved moves nothing, one moved or turned whole carries everything exactly). Points outside a mesh's cells follow its wires and outline together, each the more the nearer. Bent handles take the deform's way and stretch right at their point, so a bent line has no jogs where its pieces meet. Points outside a grid, or outside cells that all have four sides, follow the outline's sides near them: each side carries them as it is at its place nearest the point (where that went, turned as the side runs there, their distance from it kept, so a side growing longer doesn't push what lies past it out and the drawing doesn't swell as the warp moves; just past a side they slide along it as the inside does there (its shear), easing off within about a quarter of the side's length, so a line crossing the outline has no crease, while across the side they keep their distance, so a thin band hugging the outline stays thin however the inside stretches, fading out toward a side's ends where the corners are), the sides blended by the inverse eighth power of distance, so the nearest lead, it is exact on the outline, and moving one side moves only what lies beyond it. Points outside a mesh with other cells follow its outline as a cage from outside (mean value coordinates against it): smooth everywhere, exact on the outline, and far away moving as the outline does as a whole (in a hole of a mesh, that hole's outline). Frame 0 is the rest: reshaping the shape there changes what it measures from and bends nothing; (nothing bends on frame 0 at all, even mid-edit); moving or keying its points on other frames (by hand, bones or smart actions) bends the layer, handles too. **Weights** say how much each point follows: Automatic (every point of the layer fully, past the shape too, as Blender's deform modifiers bend the whole object; never stored) or Custom (a point group named after the modifier, starting from the automatic weights, painted in Weight Paint with the modifier picked in its dropdown at the top of the viewport beside Armature; points it has no weight for take the automatic one; Reset to Automatic fills it again; switching back keeps it). Weight Paint shows Automatic weights as a heat map, with Switch to Custom. A point's weight also shares it between the deform and its bones: at 1 it follows only the shape (which brings the bones' move along when the shape follows them too), at 0 only its bones, so nothing moves twice; it measures from the drawing as it was before the Armature modifier, so it goes below it (where it is added). **Strength** (keyable) scales every weight, to fade a deform in or out. **Precision** (0.002, on by default; 0 Off) is how far a bent line may stray from the true bend: where the deform would bend a segment more than its points and handles can follow, points are added there first (Illustrator's Fidelity), so straight lines bend too and barely bent ones get none. A cut fades in rather than popping in: just past Precision the pieces of a segment's last halving draw exactly as the one piece they were (the point between them where that piece has it, the handles as that piece split there), easing over (in and out) to each piece bent on its own as the bend grows to twice Precision (the drawing is bent a second time without that halving to know where), so as the shape moves and points come and go nothing jumps (a thin band, an eyelid along an eye white, doesn't flick thicker for a step and back); where those points don't all follow the deform fully, the cuts stay as they are. **Resample Self** (off by default) adds no points instead: each segment of the drawing is sampled evenly along it, the samples are bent, and the drawing's own points go where theirs went, each segment's handles fitted to its bent samples (as a sculpt stroke fits a line back): each handle keeps the way the deform turns it at its point, so a smooth point's two handles stay in line and the bent line has no kinks at its points, and only how long each is gets fitted by least squares (Schneider's fit), blended with the handles as bent by how closely each follows the samples (by the fourth power of how far each strays, on average as the root mean square, so a clearly closer one all but alone; the fit's handles held between a thousandth of the segment's chord and the chord, longer looping), so it barely strays further than without it and a small move never flips a segment from one to the other; a point the deform doesn't move keeps its own, so the drawing bends nearly as truly with only its own points; Precision is off while it is on. With Precision off (0), each segment's handles are fitted the same way (a segment whose handles as bent already follow the bend within a thousandth of its chord, checked at three places along it, keeps them, the fit easing in as they stray further), so a drawing split by a Resample modifier above the deform bends as truly as Resample Self bends it or more truly (each piece fitted), and both together more truly still; with Precision on, it has cut every segment till the handles as bent follow the bend within it. Points and handles show, and are picked and moved, where the deform puts them, and the edit wire between them follows the bend (each segment as the nearest single curve to it, its handle lengths fitted by least squares). Each deform keeps its shape's build (Rigid's and Envelope's lattice solved for where the shape is, and the lattice itself, its links and each node's mean value coordinates by where the shape is at rest) and the drawing it bent, so a frame where neither the shape, the drawing nor the modifier has changed (a held frame, the view panned, another layer edited) bends nothing anew; the drawing's points, handles and Precision's checks are shared over the CPU's cores. Rainbow Dash's skirt (Envelope, 968 lattice nodes): its cage built in 2.3 ms instead of 7.6 (40 conjugate gradient steps a round were nearly all of it), and Envelope's map of each point walks each side once less (its distance from a side is its nearest place's), so a frame whose cage moves costs 4.7 ms of bones and modifiers instead of 11.3, the points bent the same to a ten-millionth. The shape is put into the bent layer's space (at rest and as it is now), and a layer bent by bones into its armature's, from the groups the two share down (layer_relative_transform), so those groups moving (a character walked across, its top group scaled) changes them not even by rounding and the build is kept: Rainbow Dash with its top layers' scale driven, 4.9 ms of bones and modifiers a frame to 0.7, as when it plays unscaled; clay015 so, 7.5 ms of CPU a frame to 5.9. A shape bent back (through other deforms) by the layer it bends is a loop: neither bends, and the modifier says so. It can't be applied (it changes nothing on frame 0). Saved with the file. **Built-in MCP server.** Open Animate can be driven by AI assistants such as Claude through the Model Context Protocol, so they can look at and work in the running app. Moho has no such thing, which is why MohoMCP has to poll for requests inside a tool's draw call; here it is part of the app. The first version is deliberately thin while the API is still changing.

- **Built on what already exists.** Everything goes through the `oanim` Python API and its operators, so anything a person can do, the server can do, with the same undo steps.
- **Tools now:** run Python with the `oanim` module (as a console: names stay between calls, the last line's value, printed output and tracebacks come back); a screenshot of the window or one editor; the app's state (file, frame, playback, layers, selection, a running transform, recent Info reports); and pressing keys as if over an editor (typed numbers go into a running transform). Later, once the API settles: typed tools to read the document, layer tree, bones, actions and keyframes, get and set properties by path, run operators by name, set and delete keys, switch frames and actions, render a frame, and run several operations as one undo step.
- **Matching drawings to a reference.** `layer.shown(level=None)` gives where a layer's points and handle ends show (bones, parents and the layer's transform included) in document space, where a reference over the drawing is: as drawn (detail's handles final), or as detail level k's curve has them (its points only, that level's handles), with each point's place in the whole curve; `layer.set_detail_level(level, shapes=None)` sets shapes' edit level and `layer.detail_sync()` places the detail now, as the viewport does each frame (so edits at a level carry the finer detail along); `layer.place_point(i, (x, y))` and `layer.place_handle(curve, i, "IN" or "OUT", (x, y), keep_other=False)` put them there, the bones' bend undone, as a G drag would (keyed at the frame when the next undo step records it). `oanim.wm.render_png(path, width, height, guides=False, transparent=False)` renders the current frame to a PNG on the next frame drawn: guides=True includes guide layers (reference media) on a clear background and waits for the media's frame to be decoded, so a reference and the drawing render pixel-aligned (a document point lands at pixel (w/2 + s fx, h/2 − s fy), s = h/2, with (fx, fy) = camera.to_frame(point)). The project's match-vectors-to-reference skill builds on these.
- **Resources (later):** the `oanim` Python API reference and the operator list, so an assistant can discover what is available.
- **Transport:** JSON lines on 127.0.0.1 only (`src/wm/remote.cc`), run on the app's main loop between frames (screenshots from the frame just drawn), so no polling; a stdio bridge in plain Python using only the standard library (`tools/mcp/openanimate_mcp.py`) speaks MCP, registered for this project by its `.mcp.json`.
- **Safety:** off by default and switched on in Preferences (Remote Control); every request needs a token made afresh each time it starts (written with the port, the process id and the open file to remote/<process id>.json in the user data folder, one per running Open Animate, and to remote.json by the one holding Preferences' port, where the bridge reads them; removed when it stops, and left-over files of instances that crashed cleared). Several windows can each be reached: a second Open Animate takes a free port, and the bridge's list_projects names every open project while each tool takes `project` (a file name, path or process id), the main one otherwise; a connection that doesn't open with a request, as a browser's doesn't, is closed unread. Later: a separate switch for running Python and a status-bar indicator while an assistant is connected.
- **How it is built:** the listener in C++, the bridge in plain Python outside the app (no MCP SDK needed: MCP's stdio protocol is small), tested end to end headless (`tests/test_remote_control.py`).

## Architecture sketch

The app is a small Blender: a C++20 core that holds the data and does the math, an operator and keymap layer that all editing goes through, and embedded Python for tools, panels and add-ons. We copy Blender's ideas, not its heavy infrastructure (depsgraph, multi-backend GPU module, raw-memory .blend files).

**Modules**

| Module | Responsibility | Blender equivalent |
| --- | --- | --- |
| `core/` | Math, containers, IDs, logging | `blenlib` |
| `data/` | Document, layer tree, vector drawings, skeletons, actions. Saved data kept apart from runtime caches | `makesdna`, `blenkernel` |
| `rna/` | Property reflection: name, type, range, getter/setter, update callback. Drives UI, Python and animation paths | `makesrna` |
| `anim/` | Animated channels, keyframes, interpolation, actions, smart bones, drivers | `animrig`, `fcurve.cc`, `constraint.cc` |
| `eval/` | Fixed evaluation pipeline that builds an evaluated copy of the scene each frame | `depsgraph`, simplified |
| `modifiers/` | Modifier type table: mirror, noise, smooth, offset, armature deform and more | `modifiers/` |
| `ops/` | Operator registry, macros, undo flag, redo panel | `windowmanager` operators |
| `wm/` | Windows, event loop, keymaps, modal handlers, split-area screen layout | `windowmanager`, `editors/screen` |
| `editors/` | One folder per editor: viewport, timeline and dope sheet, graph, layers, properties, outliner | `editors/space_*` |
| `gpu/` | OpenGL renderer, curve tessellation, overlays for bones, handles and onion skins | `gpu`, `draw` |

| `mcp/` | Built-in MCP server in Python on the official SDK; maps MCP tools to operators and properties; localhost HTTP plus a stdio bridge | None |

**Evaluation order, every frame**

1. Read each animated channel at the current frame from the mainline.
2. Apply smart actions: each driving bone's angle picks a frame in its action, and that action's values are layered on top. Then fix actions: each blends its poses' corrections by how close the pose is to each, faded toward rest by its smart actions' shares, layered on top too.
3. Solve the bone pose: forward kinematics, IK, constraints.
4. Deform bound points and layers by their bones.
5. Run each layer's modifier stack.
6. Composite layers with masks and blend modes, then draw overlays.

**Key technical choices**

- **Window, input and tablet:** SDL3. **Graphics:** OpenGL 4.5 first; Vulkan only if needed later.
- **UI:** Dear ImGui with docking wherever it can do the job, themed with Blender's default colours, font and spacing. Custom widgets built on ImGui cover what it lacks or draws differently: Blender-style number fields (a click without dragging starts typing, a drag changes the value, Shift while dragging is precise), pie menus, tabs and icons. Panels are written in Python with a `layout.prop(...)` style API so the UI toolkit can be swapped later.
- **Python:** embedded CPython 3.12+ through pybind11, exposed as a `oanim` module shaped like `bpy`.
- **Operators:** each has `poll`, `invoke`, `modal`, `execute` and an UNDO flag, as in Blender. Extrude (E) is a macro: the data operator followed by modal move (G).
- **Keymaps:** data files of (operator, key event, properties) per editor and mode, modelled on Blender's `blender_default.py`.
- **Undo:** each undo step holds the document's settings and its layers as shared, read-only copies (each without its children, the tree's shape beside them). A push compares every layer field by field with the step before (a defaulted `operator==` on everything a layer holds, so no field can be left out) and shares those that are the same, so a step costs only what changed. Undo and redo rebuild the document from the step. Steps let go of are freed on another thread.
- **Drawing big documents:** the viewport keeps what it made of each layer while the layer stays the same. Each layer has a revision (not saved, not compared) that changes when it may have: undo steps give new ones to the layers that changed (and note when the tree changed), a point move to the layers it moves each update, and any frame that may have changed things nobody said (the frame moved or plays, a script ran, a field is dragged, the mouse is down for anything but a point move, an undo or a file opened) to every layer. The scene renderer keeps each plain drawing's geometry hash and its tessellation (a drawing moved whole draws its triangles moved), and batches its plain colour steps: they wait until anything else draws, then go out in runs of up to 32 under one stencil test from a buffer kept per run, each vertex knowing its step's place and opacity, so a rig's hundreds of drawings take a few dozen draws. The edit overlays (wires, handles, point squares) are drawn on the GPU from buffers kept per layer in layer space (instanced lines widened in the shader, instanced squares and dots), made again only when the shown drawing changes. OANIM_CHECK_REVISIONS=1 compares every layer with its last frame and reports one that changed without a new revision.
- **File format:** a .oanim file: a zip holding a JSON scene description plus binary blobs for point data, with a schema version and migration functions. A big file's drawings are parsed and built on every core: one quick scan finds each drawing's text (a big drawing's points, curves and shapes in pieces), and the rest is parsed with them left out.
- **Build:** CMake with vcpkg for dependencies, on your installed MSVC 14.51 toolchain. Windows only for now; SDL3 and OpenGL keep a later macOS or Linux port possible.

**What a Python operator looks like**

```python
import oanim

class BONE_OT_smart_create(oanim.types.Operator):
    bl_idname = "bone.smart_create"
    bl_label = "Create Smart Bone"
    bl_options = {'REGISTER', 'UNDO'}

    @classmethod
    def poll(cls, ctx):
        return ctx.active_bone is not None and ctx.action is None

    def execute(self, ctx):
        bone = ctx.active_bone
        action = ctx.active_layer.actions.new(name=bone.name)
        action.smart_bone = bone
        ctx.document.edit_action(action)
        return {'FINISHED'}

oanim.utils.register_class(BONE_OT_smart_create)
```

## Roadmap

Version 1 arrives in five milestones, and each one ends with something you can actually use. No dates yet: the pace depends on how many hours a week go into it.

   *Gate: a Python operator runs from a key press and undoes cleanly.*

   *Gate: draw, fill and save a character that matches the Moho look.*
3. **Animation:** animated channels, interpolation modes, timeline and dope sheet; switch and image layers, onion skins, PNG export; frame-by-frame drawing, auto-keying, playback controls, render settings.
   *Gate: animate a walk cycle by hand and export it as PNG frames.*
4. **Rigging:** bones, point and layer binding, IK, custom bone shapes, bone colours; actions, smart bones, local armature viewport, symmetrize with _L and _R; Setup toggle for frame 0; copy, paste and paste-flipped poses.
   *Gate: a smart-bone head turn works on a rig with IK arms.*
5. **Version 1:** modifier stack and mirror modifier, free 3D view, layer depth; operator search, redo panel, keymap editing, Python console, MCP server; top bar menus, workspaces, Properties editor tabs, auto-generated API docs.
   *Gate: rig and animate a short scene end to end, no Moho needed.*

**After version 1:** graph editor, bone dynamics and physics, bone constraints; weight painting, motion paths, pose library, asset browser, video export, mesh import.

Each gate is a hands-on test; a milestone is done only when its gate passes. Rendering quality is proven in milestone 2 and smart bones in milestone 4, the two riskiest pieces.
