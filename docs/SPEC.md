# Open Animate — Feature Spec & Roadmap

Oct 18, 2026 · @Mary

## Overview

Open Animate is a private, Windows-only desktop app for 2D cut-out and vector animation: Moho's animation model inside Blender's interface and editing habits, written like Blender in C++ with an embedded Python API.

**What it takes from each**

| From Moho | From Blender |
| --- | --- |
| Smart actions (smart bones) | Fast, lag-free viewport and rendering |
| Simple layer system: groups, bones, switch layers | Mirror modifier for armatures and drawings |
| Masking | Grease Pencil-style layer masks |
| Vector drawing and point tools | Free 3D view outside the camera; imported meshes |
| Bone binding and rigging tools | Modular editors with split views |
|  | Layout and theme; a better timeline |
|  | Modal tools and shortcuts: G move, E extrude |
|  | Custom bone shapes |

**Guiding principles**

- **Moho's data model, Blender's interaction model.** Layers, bones and smart actions behave like Moho; tools, keymaps and editors feel like Blender.
- **Everything is an operator.** Every action is a named command that keymaps, menus, undo and Python all share.
- **Python is first-class.** Tools, panels and add-ons can be written in Python, the way Moho tools are Lua scripts.
- **Small first.** Each milestone ships something usable before the next one starts.

**Not in scope:** public release, macOS and Linux builds, 3D modelling, sculpting, physics simulation, a node-based compositor, or Moho file compatibility.

**Sources:** the Moho scripting API docs scraped from mohoscripting.com, community and built-in Moho Lua tool scripts, and the Blender source tree, all in the project folder. The app is private, so Blender's GPL license only matters if it is ever distributed.

## Core concepts

The data model follows Moho: a document holds a tree of layers, almost every property is an animated channel, and actions are alternative timelines stored inside those channels. Smart bones fall out of that design almost for free.

**Document.** Frame range, frame rate, canvas size (the Document tab's Resolution: W and H with a link button between them; linked, changing one changes the other, keeping the proportion they had when linked; saved with the file; Python: document.resolution_linked), background colour, a 3D camera (track, zoom, roll, pan/tilt channels), timeline markers, a shared style library and layer comps (saved sets of visible layers). Frame 0 is the rigging frame: the rest pose, never rendered.

**Setup frame (frame 0).** Open Animate keeps Moho's model: frame 0 holds the setup pose, and there are no separate rest and pose modes. Smart bones need this, because a smart action's effect is measured from its frame-0 values. Blender's clear sense of mode is added on top:

- **Setup toggle** in the viewport header, with a shortcut: it jumps to frame 0, and pressing it again returns to the frame you were on.
- **Clear signals on frame 0:** a red border on the viewport and the timeline (and a red playhead), a "Setup" label in the header, and frame 0 drawn apart at the start of the timeline.
- **Rigging tools only work on frame 0**, as in Moho: adding bones, binding points and layers, bone strength. Elsewhere they are greyed out with the tooltip "Switch to Setup (frame 0)". The toolbar has two sections: tools for every frame (Select, Cursor, Transform Bones), then frame-0 tools (Draw, Shape, Split Curve, Weight Select, Weight Paint), greyed out elsewhere with the tooltip "Only available on frame 0"; a frame-0 tool hands over to Select away from frame 0 and comes back on it.
- **Auto-keying never applies on frame 0**, because changes there edit the setup pose and carry into every frame.
- **Keys are changes from the setup pose**, as Blender's pose bones and shape keys, Spine's deform keys and Harmony's deformers keep them (Moho keeps own values): a bone's keys hold its Transform (along the bone's rest axes) and Angle; a point's its Transform, applied before bones bend the drawing, so a keyed shape follows the bones; a handle's its Handle Angle and Length (the turn, and the length added), so a handle swings along an arc between keys. Away from frame 0 the Properties editor shows these, 0 at rest: the Bone panel's Transform and Angle, the Point and Shape panels' Transform, and the Point panel's Handle In and Handle Out Angle and Length (an aligned partner turns with it). Reshaping frame 0 after animating keeps every pose's motion. A point added to an animated curve (Split Curve) takes its neighbours' motion, blended by distance along the curve (past an end, the end's), so adding points doesn't break the animation. Older files and Moho imports open converted.

**Layers.** Every layer has a name, a stable ID, visibility, lock, label colour, an origin, animated transform channels (position, scale, X/Y/Z rotation, shear, flip), opacity, blend mode, masks, an optional parent bone, a timing offset and a modifier stack. Types for our app:

| Layer type | Holds | Version |
| --- | --- | --- |
| Vector | Points, curves, shapes and styles | v1 |
| Group | Child layers; its masks apply to everything in it | v1 |
| Bone | A group that owns a skeleton and controls its children | v1 |
| Switch | A group that shows one child per frame, chosen by an animated name | v1 |
| Media | Images, image sequences, video and sound, as clips along the timeline; a Guide by default (shown while you work, never rendered) | v1 |
| Mesh 3D | An imported OBJ or glTF mesh placed in the scene | Later |
| Text | Editable text turned into vector shapes | Later |
| Particle | Child layers emitted as particles | Maybe |
| Note | A sticky note in the viewport | Maybe |

**Vector drawings.** A drawing is a pool of points, curves through those points, and shapes. A point can sit on several curves, which is how Moho welds lines together. Each point has an animated position, an animated width and an optional bone binding. Every curve point has two Bezier handles, and every handle is free, like Blender's Free handles: stored, and moved only by hand (or with its point). A new point gets its handles once, from Moho's smooth spline (curvature, weight and offset) or, at corners and straight sides, a third of the way toward its neighbours. Align (right-click a selected point or handle) lines a point's handles up and keeps them in line: moving one turns the other. Right-clicking selected points edited from another layer (a bone layer, or several layers at once) also offers Select Layers of Selected Points: the layer holding them becomes active (others with selected points are picked), the points staying selected. Alt-dragging a handle moves it alone and unaligns the point; Unalign does the same without moving anything. Peak and Smooth set a point's handles once (straight, or smooth and aligned). With one point selected, the Properties editor's Point panel shows its handles as **Handle In** and **Handle Out** rows, each an Angle (degrees, counter-clockwise from the layer's x axis) and a Length (how far it reaches from the point), as Moho and Illustrator give handles; an open curve's first point has no In row and its last no Out; a point on several curves shows each curve's, numbered; a handle picked on its own shows just its row. Changing one moves the handle (an aligned partner turns with it), one undo step (Move Handle); away from frame 0 they show how far the handle has turned and grown from the setup pose instead, 0 at rest. A **Transform Points** tool in the toolbar (for drawings; any frame) puts the same box gizmo Transform Bones has round the selected points and handles picked on their own, in the active layer's space: drag inside to move (Shift keeps to one axis, Ctrl snaps to a point), the band around it to turn about the pivot (Shift: 45° steps), a handle to scale (Alt from the pivot, Shift keeps a corner's proportions); Ctrl on a side handle shears instead (as Illustrator's and Inkscape's: a top or bottom handle slants the points along x, a left or right one along y, the opposite side staying, or the pivot with Alt; the cursor shows the way, and the undo step is Shear Points); while the box moves, turns, scales or shears them, the points and handles aren't drawn, so the shape is what's seen; curve handles don't show (nor can be picked) while it is the tool, and with the overlays off (Shift Z) the box, as Transform Bones' box, isn't drawn and clicks select, the pivot to move it (Ctrl snaps to a point); outside, a click selects and a drag box-selects. Points move as G, R and S move them: across every edited layer, through their bones, with mirror and proportional editing, keyed away from frame 0. Its header has Position (the pivot), Scale, Angle, Flip H, Flip V and Symmetrize; they run mesh.transform_selected (move_x/y, scale_x/y, angle, pivot_x/y). **Mirror** (right-click with points selected, a submenu as Blender's: X Global, Y Global, X Local, Y Local) flips the selected points, and handles picked on their own: Global along the document's axes through their layer's origin (each layer's own, when several are edited), Local along the active layer's own axes (turning with it) through the middle of the selection; through their bones, with mirror and proportional editing, keyed away from frame 0, one undo step ("Mirror X Global"), the options in the ViewportActionPanel; Python: oanim.ops.transform.mirror(axis="X" or "Y", orientation="GLOBAL" or "LOCAL"). **Symmetrize** (right-click with points selected) makes the selected points mirror images across the layer's vertical axis, copying one side onto the other (Right to Left by default): points within the Threshold of the axis snap onto it and their two handles mirror each other (made flat when within 10° of flat, so one point on the axis just evens its handles); the others pair up by where each one's reflection lands nearest in the setup pose, and each copy takes its partner's place, handles (reflected), width and corner (and, with Weights, its bone weights, _L and _R swapped). Each side needs as many points as the other: otherwise nothing changes, the status bar warns ("Uneven sides: 2 on the right, 1 on the left") and the points without a partner are selected. On frame 0 it reshapes the drawing; on other frames it mirrors the pose (each copy's Transform becomes its partner's, reflected, and auto-key keys it). Viewport Overlays > Handles shows None, Selected, Shape (the default: every handle of the shapes being worked on, any of whose points is selected) or All; Point Size and Handle Size under it (pixels across, 2 to 24; 6 and 6.5 by default, as Blender's Vertex Size) set how big points and handles' ends are drawn, a click reaching a little past them; Edges selection mode shows none, as it picks segments rather than points. A shape is a list of curve segments with a fill and outline style. Styles cascade: a shape has its own style plus up to two shared styles from the library.

**Bones.** A skeleton is a tree of bones. Each bone has a rest position, angle and length plus animated position, angle and scale channels. Scale is X (across the bone: its thickness) and Y (along it: its length), as Blender's bone axes, and is for posing only: on frame 0, S resizes bones instead. Bones support IK with locks and angle limits, independent angle, maintain volume (squash and stretch), controlling bones (one bone's angle drives another's), bone dynamics (bones hang like weighted strands that swing, jiggle and stretch as the body moves), colour tags and a display shape. Points follow the bones by weights, as Blender's vertex groups: new points get automatic weights (nearer bones pull harder, a bone's strength widens its reach), and weights can be assigned or painted. A whole layer can be parented to one bone instead.

**Local armature viewport.** Every armature has two places its bones can live. **Viewport bones** sit in the scene: they move the character, deform artwork and show in the normal viewport. **Local bones** live in that armature's own local armature viewport, a separate canvas that belongs only to it, and never appear in the main viewport. This is where control bones go, such as smart-bone dials, sliders and switches, so they stop floating around the workspace. Both kinds belong to the same armature and key onto the same timeline. Bones are added and edited the same way in either place.

- **Control-only.** Local bones drive smart actions and can be controlling bones for viewport bones, but they cannot bind or deform artwork.
- **Separate trees.** A local bone can only be parented to another local bone, never to a viewport bone, and vice versa.
- **Helper artwork.** The local viewport can hold drawings that never render: labels, slider tracks, a face image to click on. Together with the local bones this makes a rig control board.
- **An editor type.** "Armature" is an editor you can put in any split area. It follows the selected armature and can also open as a floating window. Turning a dial there updates the character in the main viewport live.

**Animated channels.** One typed channel class covers numbers, 2D and 3D vectors, colours, booleans and strings. Channels can split into separate X/Y channels, be muted, and have keys selected for the timeline.

**Interpolation: Moho modes on the surface, Blender F-curves underneath.** Each key is stored like a Blender keyframe: a value, an in-handle and an out-handle, and a per-key interpolation mode. The modes are Moho's full set plus Blender's Back easing. Most modes compute their handles automatically, so they behave exactly as in Moho; in the graph editor, dragging a handle turns the key into a Bezier key, the way Blender's auto handles become free. Moho's per-key extras sit on top: a hold length, an interval for animating on 1s, 2s or 3s, a stagger flag and a colour tag. New keys get the new-key mode (saved with the preferences; Smooth to begin with), or, with Copy Previous Key on, the mode and settings of the key before them.

| Mode | What happens between this key and the next | Settings | Handles |
| --- | --- | --- | --- |
| Linear | Constant speed | — | None |
| Smooth | Eases through the key using its neighbours, clamped as Blender's auto-clamped handles: equal neighbouring keys hold still and the motion never overshoots a key | — | Automatic |
| Ease In/Out | Starts slowly and slows into the next key | Strength | Automatic |
| Ease In | Slows into the next key | Strength | Automatic |
| Ease Out | Starts slowly from this key | Strength | Automatic |
| Step | Holds the value, then jumps at the next key | — | None |
| Bezier | Custom curve | In and out angle and length per component | Free, aligned or vector, as in Blender |
| Back | Overshoots slightly, then settles (from Blender) | Overshoot amount | Formula |
| Bounce | Bounces into the next key | — | Formula |
| Elastic | Springs past the next key and settles | Amplitude (how far the first swing goes), period (how long each wobble is) | Formula |
| Noisy | Random jitter around the interpolated value | Amplitude, frequency | Formula |
| Cycle | Loops back to an earlier key | Frames back, or an absolute start frame | Copied from the cycled keys |
| Pose | Holds a value taken from an action | Which action pose | From the action |

All modes also take the hold length (frames to wait before moving) and the interval (1s, 2s, 3s). The Ease modes' Strength is one of Robert Penner's easing families, from Gentle (Sine) through Quad (the default), Cubic, Quart and Quint to Strong (Expo), plus Circ. Because keys share Blender's storage, drivers can later use the same curves.

**Picking a mode.** A key's interpolation is for the stretch arriving at it from the key before, as Moho's: how the motion gets to this pose (Step holds the key before, then jumps to this one; Ease In slows into this key). Its curve settings (Strength, Overshoot, Amplitude and Period, Amount and Wiggles) go with it; Hold, Animate On and Cycle are for after the key (Cycle loops after its key, so the stretch into a Cycle key is Smooth). The first key's mode does nothing. Files from before (format 3 and older, the Moho converter's too) had each key's curve for the stretch after it: opened, each moves onto the key after, so their motion stays the same. Smart actions play the stretch to their first key with that key's curve too, as the action shows when edited (before, always Smooth). The timeline's header has an Interpolation dropdown, as Moho's: with keys selected it sets their mode (it reads Mixed when they differ); with none selected it sets the mode new keys get. T over the timeline opens the same menu at the mouse, and right-clicking a key has it under Interpolation (the right-clicked keys join the selection first). Every item shows a small drawing of its curve, in groups: Smooth, Linear and Step; Ease (Ease In, Ease Out, Ease In/Out, and a Strength submenu); Bouncy (Back, Bounce, Elastic); Special (Noisy, Cycle). Bezier isn't offered: dragging a handle in the graph editor makes it. The menu also has Copy Previous Key, Copy Interpolation and Paste Interpolation (one key's mode and settings onto the selected keys, their values untouched), Use for New Keys, and Settings. The settings button beside the dropdown (or Settings in the menu) opens a panel with the selected segment's curve, drawn as progress from the key before (0) to this one (1), and the mode's own settings: Strength, Overshoot, Amplitude and Period, Amount and Wiggles, Loop Back; then Hold and Animate On (1s, 2s, 3s). A change goes to every selected key (a drag is one undo step); with no keys selected it changes what new keys get. A yes/no property's keys (visibility) stay Step whatever is chosen.

**Keys show their mode.** In the timeline a key's shape tells its family: a diamond for Smooth, a thin diamond for Linear, a square for Step, a circle for the Ease modes, a star for Back, Bounce and Elastic, and a hexagon for Noisy and Cycle; a frame where the keys of a row differ is a diamond. (A key whose handles were dragged gets a mark once the graph editor can drag them.)

**Stepped Preview.** A stairs button after the playback buttons (also Playback > Stepped Preview) plays everything as Step, holding each key until the next, to judge the timing of the poses while blocking. No key changes; turning it off brings the curves back.

**Actions.** An action is a named, alternative timeline that lives inside every channel of a layer; the regular timeline is the mainline. Actions belong to a bone layer and cover it and everything inside it. Editing an action switches the whole document into that action: its keys are swapped into the channels, layers outside the bone layer keep the mainline, and frame 0 stays the shared setup pose (editing it in an action changes the setup, and every bone pose with it). Actions can be inserted into the mainline as a copy or by reference, and blended.

**Smart bones.** A smart bone is an action with the same name as a bone. Inside the action, the bone's own angle is keyed over time, for example 0° at frame 0 and 90° at frame 24. On the mainline, the bone's current angle is looked up in that keyed range to find a matching action frame. Every other channel in the action is sampled at that frame, and its change from frame 0 is added on top. Visibility and Draw Order hold each key until the next, so they switch when the bone turns past a key's frame, never blending (a head turn that hides an eye at frame 24 hides it once the head turns past that frame's angle). Influences from several smart bones always add together. A second action named after the bone plus " 2" handles rotation in the other direction. It plays live while the smart bone is dragged, moving its bones and their points as it turns (bones the action moves without keys of their own included). On the setup frame (0) a smart bone plays nothing: turning it there sets its rest angle, as in Moho.

**Masking.** A layer's masks are **cards** whose steps name other layers (as Rive's and Figma's boolean stacks, After Effects' mask modes and Live2D's clipping); **Mask cards** below says how a card is built and how cards combine. Below, a row's shape settings are a step's, and Affects, End Lines at Edge, Ends, Reach and the viewport and render switches are its card's. Several layers in one row act as one shape (their union); a group named means all of it. A row takes its layers' shapes as drawn, before any masks of their own (those mask how a layer shows, not the shape it lends; only Clip to Below takes what its base shows); a file from before this lists, when opened, the layers whose masks named a layer with masks of its own. Each row has Invert (use what's outside its shape), Grow (pixels; negative shrinks; a pixel hides thin seams along the edge), Shape (which parts mask: As Drawn, fills and strokes as drawn; Fills Only, Moho's option, without strokes; Strokes Only, just the lines), Fill Every Shape (a checkbox: the inside of every shape masks, filled or not, an open one closed straight across, as Rive clips with a shape's path; greyed out with Strokes Only, and the summary then reads "on ring's lines"), Inside the Stroke (a checkbox, with Fills Only: the fills end at their lines' inner edge rather than down their middle, at any zoom, and wherever the line is drawn (a brushed line's turned or jittered dabs reach past its width, soft edges included), so an arm cut by a body shows over the body's whole outline where they join, as a copy of the body's fill on top would), Cuts (what of the masked layer the row masks: All; Fills, its fills only, as Toon Boom cuts colour art apart from line art; or Lines, its lines only, ended or sliced, its fills showing as if the row weren't there, so a head and an ear that cut each other's lines where they join keep both fills rather than leaving a hole where they overlap; picking and Clip to Below go by the fills; the summary adds "(its lines)" or "(its fills)"; a file with the older Lines Only opens as Lines), End Lines at Edge (a checkbox: the masked layer's lines end where they cross the row's shape, worked out along them before a brush lays its dabs, instead of being sliced there, with Ends: Brush (the line stops short of the edge with whole dabs, so nothing crosses it, with the brush's own taper and fade, and isn't sliced by the row's pixel clip; its Reach, in line widths from -2 to 2, keyable and drivable, moves the end: 0 just touches the edge, 0.5 puts the last dab's middle on it, more runs past it, less leaves a gap) or Flat (the line then cut straight along the edge); fills are masked as always, unless Cuts is Lines; with Cuts Fills it does nothing; the parts cut away show as faint dashed wires; a group's row ends the lines inside it; an Add row after one that ends lines ends them too, with that row's Ends, so it brings back the lines that row ended without End Lines at Edge on itself (the card says so under its checkbox); the summary adds "lines ending at head's edge"), Extend (None, Up, Down, Left, Right: the shape stretched to the edge of everything that way, in the mask layer's own directions, turning with it and its bone; a filled shape, or any with Fill Every Shape, stretches all of it, an outline-only one just the edges it draws, so Subtract the mouth line extended Up hides the mouth and everything above it, letting teeth show over the lower lip without a hand-drawn shape) and its own viewport and render switches, as modifiers have. **Clip to Below** (Photoshop's clipping mask) shows a layer only where the layer below it shows, as it shows: only its visible layers count (hidden ones and, in renders, guides don't), each cut by its own masks as drawn; several layers in a row can clip to one base, the first layer below them that doesn't clip; it applies after the rows. Its Exclude Strokes (under the checkbox) clips to the base's fills only, so shading stops inside the outline instead of covering it. A group's mask applies to everything in it. Masks don't depend on Draw Order or visibility: a hidden layer still masks (a mask shape is usually kept hidden), and one mask layer can mask many layers. A mask layer's own mask counts (its shape masks only where its rows show it). Copied together (Duplicate with both picked), a layer and its mask layer stay a pair: the copy is masked by the copy; a reference of a group masks itself with its own copies. Where they are set: the Layers editor shows a masked layer with just a mask symbol after its name, no text (orange, the colour masks are shown in everywhere; grey when all its rows are off): hovering it lists the rows and the result in words and outlines their layers in the viewport, and clicking it opens the Masking tab. A clipped layer is indented with an orange hook pointing down to its base. **Alt-dragging** a layer onto another adds a row of it there (Add; Shift: Subtract). **Alt-clicking** the line under a layer (the lower part of its row) clips it to the layer below, or releases it; **Ctrl Alt G** does the same for the picked layers. The Masking tab in Properties (next to Layer) starts with the result in words ("Shows: inside head, minus mouth, plus tongue"), a row to a line ("Shows:", then "everything but head", "plus tongue", "minus mouth and above"; hovering a line outlines its row's box and layers, clicking it opens and scrolls to the row), then Add Mask (a menu: Show Inside a Layer... starts a card on black with + Shape, Hide Inside a Layer... on white with - Shape; then click the mask layer, in the viewport or the Layers editor), Join Lines (with two layers picked that meet, a head and an ear: each gets a Subtract row of the other with Fills Only, Inside the Stroke and End Lines at Edge, the lower one's cutting only lines so its fill covers the overlap; a row already naming the other is reused) and the Clip to Below checkbox ("Clipped to base" under it), then a box per row as the Modifiers tab shows modifiers (Blender 2.90's panels): a header (open arrow, a white or black swatch for its Start With, its name ("Mask 1"), or folded the row in words ("minus Ear_L (its lines), lines ending at Ear_L's edge"), viewport and render switches, a menu with Duplicate, Move to First, Move to Last and Delete, an x that deletes it, and a grip to drag it up or down, which can change the result) and, folded inside, Layers (a chip per layer, x taking it out; + for the list of layers to tick, the eyedropper to click one; hovering a chip, or a layer in the list, highlights it in the Layers editor and outlines it in the viewport), Invert (use the outside) and Affects (the Cuts setting) with **View** at its end (a half white, half black square): while it's held down, the viewport shows the mask as it stands after this row, over the drawing at 90% so the art shows faintly through: white where the layer's fills show (its lines, when the row affects only Lines) and black where they're hidden, its groups' masks counting, with a label saying which ("Lines mask of Ear_L after row 2 (Ear_Line_Show): white shows, black is hidden"); rows that leave that part alone are left out and rows that end lines count by their shapes; letting go shows the drawing again (viewport only, never renders), then two subpanels, folded at first, whose bars open them and, folded, show what's set inside ("Fills, inside the stroke, +1.0 px, extended up"; "Brush, reach 0.34"): Masking Shape (Mask With, the Shape setting, with Fill Every Shape and Inside the Stroke indented under it, Grow and Extend) and Line Ends (End Lines at Edge, then Ends and Reach, greyed out while it's off). Settings with a few choices (Affects, Mask With, Extend, Ends) are rows of joined buttons, Blender's expanded menus, with icons (fill and line, fill, line; arrows for Extend). A row that's off in the viewport is faded. Hovering a row outlines its layers in the viewport. On a mask layer, a Used as a Mask section below lists the layers it masks or that clip to it (click one to select it). The Mask menu (the Layers editor's right-click menu, and the viewport's right-click menu with nothing selected) lists the rows and has Clip to Below, Add Layer..., Subtract Layer..., Join Lines and Remove Masks. In the viewport the active layer's mask layers are outlined dashed in orange, labelled (Viewport Overlays > Drawing > Mask Outlines turns this off; they still show while a mask symbol, row or Layers field is under the mouse). Undo steps say what happened ("Mask head: Subtract mouth hole", "Clip stripe to base"). Rendering evaluates each masked level's rows in order in the stencil (a result bit per level, a scratch bit for each row's shape; shrinking clears a band around each area's edge). Files from before rows, whose masks said Inside or Outside and all had to hold, open exactly as they looked: an Outside mask becomes Subtract, an Inside one Add as the first row and Subtract with Invert after, Expand a 1 pixel Grow, and Mask With Layer Below becomes Clip to Below's operator. Files from before that, with Moho's masking groups (Hide all / Reveal all, each layer Masked, Add, Subtract or Clear), open with those turned into rows (a mask layer's old Expand and Fills Only going to the rows naming it): an Add row of the layers added before it (since the last Clear) and a Subtract row of the ones cut, and the masking-only layers become hidden layers. The Moho converter leaves masking out. Files from before cards convert as Mask cards below says. Python: layer.masks (cards and their steps; see Mask cards), layer.mask_summary, layer.clip_to_below, layer.masking, oanim.ops.mask.add / set / remove / move / duplicate / join_lines / clip_to_below.

**Mask cards.** Each card is a mask of its own, painted as Photoshop's layer masks are: it starts white (**Start With: Everything**, all shown) or black (**Nothing**), and its steps, read top to bottom, each paint their shape on it: **+ Shape** paints white (shows inside it), **- Shape** paints black (hides inside it), and a step's Invert paints the outside instead (- Shape with Invert keeps only what's inside). A step's shape is all its layers together (a chip each), with its own Shape (As Drawn, Fills Only, Strokes Only), Fill Every Shape, Inside the Stroke, Grow and Extend. The card says what of the layer it masks (Affects: All, Fills or Lines) and how it cuts lines: sliced by pixels, or, with End Lines at Edge, ended where they cross the edge of the card's whole shape (Ends Brush or Flat, Reach). The layer shows only where every card that masks that part shows it: cards multiply, so one can only hide, never bring back what another hid, and a card that leaves the fills alone doesn't touch them. So a head can have one card for the ear (Everything, - Shape Ear_L, + Shape of the outside of Ear_Line_Show, lines ending at its edge) and another for the neck (Nothing, + Shape Head_Base_X). A card's first step sets its Start With (+ Shape: Nothing; - Shape: Everything), and so does changing a lone step's mode; after that it changes only by hand. Clip to Below is a card of its own that starts from everything. In the Masking tab each card is a box: its header has the open arrow, a white or black swatch for its Start With, its name, a field edited in place as a modifier's (one undo step, "Rename Mask"; left empty it reads "Mask 1" by its place, and a named card's line in the summary starts with its name; hovering it shows the card in words), the viewport and render switches, a menu (Duplicate, Move to First, Move to Last, Delete), an x and a grip; inside, Affects with View first, Line Ends under it, then Start With (two joined buttons, a white and a black square), the steps (each a +/- pair of white and black squares, its layer chips with + and the eyedropper, an x that takes the step out (a card keeps one), Invert, and its Shape subpanel, folded), + Shape and - Shape (a new step, then click its layer). The summary at the top says each card on a line ("fills: everything but Head_Base_X", "lines: everything but Head_Base_X, plus Ear_Line_Show, lines ending at the edge"). Add Mask makes a card (Show Inside a Layer... starts it on black with + Shape, Hide Inside a Layer... on white with - Shape, then click the layer); Join Lines makes one card on each of the two layers. Rendering puts a layer's cards in up to three stencil levels by what they cut (fills and sliced lines, fills only, sliced lines only), each card worked out in a spare bit and kept only where the level already shows. Files from before cards turn each layer's rows into cards that show the same: the rows that masked its fills become a fills card and those that masked its lines a lines card (one card for both when they're the same rows), each starting where the layer's Start With, or its first row, said, the lines card ending lines if a row did; an Intersect row becomes - Shape with Invert flipped, a Difference row + Shape, and a row that was off a card of its own, off. Python: layer.masks (cards: name, start, cuts, end_lines, ends, reach, enabled, render and steps: mode ADD or SUBTRACT, invert, layers, grow, shape, filled, inside_stroke, extend; a card's first step's keys are on it too), oanim.ops.mask.add (a new card; card= adds a step to one), mask.set (name=, start= and the card's settings; step= for a step's), mask.remove and mask.move (step= for a step), mask.duplicate; drivers: masks[i].start / cuts / end_lines / ends, masks[i].steps[j].mode / invert / grow / shape / filled / inside_stroke / extend.

**Draw order.** Every layer has a keyable Draw Order: Normal (where the Layers editor puts it), In Front Of a layer, or Behind one. Its keys hold until the next key, as visibility's do. A rule can name any layer in the document, across groups and bone layers; a rule on a group moves the whole group; rules are settled outer groups first, then in the Layers editor's order. Masks name their layers, so a masked layer drawn in front of another layer is still clipped to its own mask. A group faded below full opacity is drawn as one image, so nothing inside it can leave it: a rule inside it that names a layer outside moves the whole faded group (the Draw Order row and the Layers editor say so). A rule naming a layer that is gone draws as Normal and shows "(missing)". On frame 0 the commands set the setup order; on any other frame they key it. **Ctrl ]** / **Ctrl [** (Bring Forward / Send Backward) move a layer past the next drawn layer that overlaps it, so every press shows (past one that doesn't only when none does); with **Shift**, Bring to Front / Send to Back. A step that lands where the Layers editor has it anyway goes back to Normal. **In Front Of... / Behind...** wait for a click on the other layer, in the viewport or the Layers editor: the layer pointed at is outlined and named, and the result shows before the click; Esc cancels. The Draw Order menu (right-click in the viewport with nothing selected, the points' right-click menu, and the Layers editor's right-click menu) has these and Normal, under "Now: In Front Of Torso". The Layer tab's Draw Order row has the mode, the layer (a list or the eyedropper) and the key button. The Layers editor marks a layer drawn out of place on this frame with an arrow (up in front, down behind; red when its layer is gone): hovering says what it's drawn in front of or behind, clicking selects that layer. Its Order button lists the drawing layers in this frame's draw order instead of the tree, each with its group; dragging one onto another (upper half in front, lower half behind) sets its rule. In the timeline a Draw Order row (under the layer's Props, beside Opacity and Visibility; with Group by Kind, in its own Draw Order section) has square hold keys and, between them, a bar naming the rule in effect ("In Front Of Torso", or an arrow and the layer's name where the bar is short); hovering a bar outlines both layers in the viewport. Keyed Here lists it as "Draw Order: In Front Of Torso". Undo steps say what happened ("Hand In Front Of Torso"). Viewport clicks that pick a layer take the topmost as drawn. Python: layer.draw_order, oanim.data.draw_order (names as drawn, bottom first), oanim.ops.layer.draw_order_set(mode=, target=).

**Symmetrize layers.** The Layers editor's right-click menu has **Symmetrize + to -** and **Symmetrize - to +**: they make the other side of the active and picked layers, and of the layers in picked groups, mirrored across the document's vertical axis (x = 0); inside a bone layer, across the bone layer's own axis, the line bone Symmetrize uses. Partners pair by name, with the same left/right rule bones use (Ear_L and Ear_R, L arm and R arm, Left and Right; a trailing number kept). Each pair copies from whichever of the two sits on the side the command copies from (the middle of its drawing's box on the setup frame), whatever its name says, so either can be picked. A missing partner is made just above the source, in the same group, so a Clip to Below source and its copy clip to the same layer. An existing one is remade in place: it keeps its name, its place and its id, so masks naming it still do. A group named for a side goes as a whole: its layers flip their names where they have a side, keep their ids when they're remade, and are numbered when a name is taken ("Sleeve 1"). The copy's transform is the source's mirrored, and the layers inside it get their position's x and their rotation negated, so they move and turn the way the source's do. Drawings flip with their handles, widths, corners and detail points. Bone weights and Parent Bone move to the other side's bones (brow_L to brow_R). Mask rows and Draw Order naming a sided layer name its other side (a row of Eye_L becomes Eye_R; Head_X stays). A reference is copied as a plain layer showing what it showed. A picked drawing named for neither side is symmetrized in place, as point Symmetrize does with all its points (each needs a partner across the layer's axis, or it's skipped). It works on the setup frame only. The copies rest in the setup pose: no point, handle or transform keys, so animate them after. It's one undo step ("Symmetrize + to -"), and the status bar lists what it made, remade, symmetrized and skipped (with why: "not on the + side", "3 points on the right, 0 on the left"). Python: oanim.ops.layer.symmetrize(direction="POSITIVE_TO_NEGATIVE" or "NEGATIVE_TO_POSITIVE").

**Copy and paste layers.** With the mouse over the Layers editor, **Ctrl C** copies the active layer and the picked ones, with everything in them, and **Ctrl V** pastes them above the active layer, in its group, into this file, another file or another running Open Animate (they travel on the system clipboard). They paste in their order, the one that was active when copied active again and the others picked; one undo step ("Paste 2 Layers"). Names already taken are numbered ("Ear_L 1"). Masks and Draw Order naming layers that came along name the pasted copies; ones naming layers left behind find this file's layer of the same name, and a mask row with none left goes. A shared material with the same name and look is reused, otherwise it is added (its name made unique). Pasted into a bone layer, Parent Bone and weights find its bones by name (a weight for a bone it doesn't have goes, so a point left with none gets automatic weights); pasted outside one, they let go. A reference whose original wasn't copied pastes as a plain layer showing what it showed; drivers wholly inside the copy come along. Python: oanim.ops.layer.copy(), oanim.ops.layer.paste().

**Reference layers.** A reference layer is a live copy of another layer or group, in the same file or in another .oanim file. It shows the original's drawing, bones, smart bones and animation, and updates as the original changes. Open Animate copies Moho's rules:

- **Layer channels follow the original** (location, rotation, scale, opacity, animation and all) until you edit or key that channel on the reference. The channel is then changed on the copy: teal in the Transform panel and the timeline, where right-clicking it offers Reset to Original (its keys go too) and Push to Original.
- **Settings that are not keyable stay local** to each reference: masks, blend mode, label colour, lock and similar. This is what makes advanced masking work. A hidden reference of an animated body can be the mask of shading, textures or outlines anywhere, so they are clipped to the body's exact animated shape with no extra animation.
- **Referencing a group** references its whole tree; every child is itself a reference.
- **Making one:** **Alt D** in the Layers editor (Blender's Duplicate Linked; Shift D is an ordinary copy), the Layers editor's Ref button or right-click › Reference Layer: Duplicate as Reference, a reference of the active layer just above it.
- **A reference of a reference links to the original** (references never chain): Duplicate as Reference on a reference, or on a referenced group, makes a plain reference of the original layer (inside a group, of each original layer), without the copy's own changes. Files with a chain, made before this, open with it linked to the original.
- **Its own changes, each kept apart** (overrides, as Blender's library overrides, Unity's prefab overrides and Figma's instances keep theirs), found by the original's permanent point and shape ids so they stay on the right ones as the original changes. Everything not changed follows the original.
  - **Looks:** per shape and per setting (fill colour, line colour, line width, brush, fill and outline on), edited in the Shape tab's Shape panel as on any layer; a colour, line width or brush changed on a copy shows a revert button beside it in the Shape panel, and with its points locked the shape's Position is greyed out (point editing is locked); a shape of the original can be hidden on the reference only (from Python, layer.reference_hide_shape; listed under Changes, to reset); an edge can be hidden or shown on the reference only, with the Edge panel as on any layer, whether its points are locked or not (kept by the ids of the points at either end; Reset Looks brings back the original's); the Reference tab's **Recolor** has just Reset All Shape Styles and Push All Shape Styles (every colour, line width, brush and fill or outline changed on the copy, at once; hidden shapes stay hidden). Colour swaps (one colour of the original recoloured on every shape using it, the ones added later too) can still be made from Python (layer.reference_swap_color) and are listed under Changes.
  - **Points: Locked / Editable** (the Reference tab, or the lock in the viewport header beside Points / Edges / Strokes; locked by default, so points don't move by accident): moving a reference's points keeps offsets from the original's points, keyed like any edit; the offsets' keys add to the original's motion. **Follow Original's Animation** (under More, on by default); off, only the original's setup shape shows, with the reference's own keys. Handles turned or dragged are kept as offsets too (found by their point and the neighbour each points toward), added to the original's handles the same way. Widths and curve types stay the original's, and points can't be added or deleted (a message says so; Break Reference to change the drawing).
  - **Pose: Same as Original / Own Bones** (Same as Original by default): the reference shows the original's final shape, posed by its bones, smart bones and dynamics, wherever it sits (even outside the bone layer, as exact masks need); the top reference's own transform takes the place of the original's (and follows it until taken over), and everything inside a referenced group follows the original. With Own Bones, it binds to its own bone layer, starting with the original's weights by bone name (or automatic ones); its weights are its own, and Weight Paint changes them without touching the original's. Its Parent Bone is greyed out until it has Own Bones (posed Same as Original, it moves with the original's bones, so a parent bone set earlier waits).
  - **The Reference tab** (on references) holds everything about the link: "Copy of <original>" with Go to Original and how many changes it has, then a dropdown each: Pose, Points and Recolor (open), **Changes on This Copy** (folded to start with: grouped as Colors, Shapes, Points, Layer Animation and Bone Weights, each opening to its items, clicking one picks it in the viewport, with Reset and Push on each item and group) and More (Follow Original's Animation, Remove Unused Changes); Break Reference apart, with a warning. One vocabulary everywhere: **Reset** (back to the original) and **Push** (written into the original, so it and every copy get it; hiding and own weights stay the copy's).
  - **Changes show where they are:** a value the copy changed shows teal where it's edited (the Shape panel's settings, Transform, Opacity, Mean Position, the timeline's rows), as Blender shows overridden properties, and right-clicking it offers Reset to Original and Push to Original. The Layers editor marks a copy with changes with a teal dot, and while a copy is selected its original's row is outlined (or the folded group holding it). Something not allowed on a copy (deleting or adding its points, moving them while locked, changing widths or curve types) is undone, and a warning shows in the status bar's reports banner, as in Blender (also when a copy's selected points stay put while other layers' points move, as when editing from a bone layer); the same goes for the viewport's and rigging's other refusals (drawing away from the setup frame, changing the rig away from it, a bone hanging from its own child).
- **References to another file** show a warning when the original has changed. Updating offers Moho's options: add new layers, remove missing layers, replace mismatched bones, replace mismatched drawings.
- **Break reference** turns it into an ordinary layer that keeps what it shows, its offsets added to its points' keys so its animation stays as it was. A reference whose original is deleted does the same.
- **Better than Moho:** each channel stores its override flag explicitly, so a reference never silently gains keys or loses its link. Moho users report both problems ([forum thread](https://lostmarble.net/forum/viewtopic.php?t=37872)).

Sources on Moho's behaviour: the scripting API (`DuplicateLayer` by reference, `UpdateReferencedLayer`, `MohoLayerRefSyncOptions`) and [this forum thread](https://lostmarble.net/forum/viewtopic.php?t=34787).

**Tools.** A tool is an object with mouse, key and tablet callbacks, an overlay draw callback, an options bar, saved preferences, and checks that hide or grey it out by context. That maps directly onto our Python tool class.

## Feature spec

"Community" means a feature that Moho users built as add-on scripts, so it becomes native here. Speed is a requirement throughout, not a feature: the viewport should play back at the document frame rate.

**World/Camera view toggle.** A toggle button in the viewport header switches the view between Camera and World; Numpad 0 does the same, as in Blender.

- **Camera:** you see exactly what renders, framed by the camera. The camera tools (track, zoom, roll, pan/tilt) move the scene camera.
- **World:** a free view you can orbit, pan and zoom around the whole scene. Layers show at their real depth, the camera appears as an outlined frame you can select and move, and imported meshes are visible from any angle.
- Each viewport remembers its own World position, so toggling back returns you to where you were. In a split layout, one viewport can stay in Camera while another is in World.

**The camera.** The canvas is infinite: the background goes on past the camera's frame. The camera is pinned at the top of the Layers editor; it isn't a layer, so it can't be moved in the list, hidden or locked. At the origin, zoom 1 and unrolled, its frame is where the page always was (2 units tall), so files from before cameras open unchanged.

- Picking it (its Layers row, or a click on its frame's border where nothing else is) makes the viewport look through it, as Blender's Lock Camera to View: the view fits the frame, drawn orange, and panning and zooming move and zoom the camera, one undo step per gesture. With it not picked the view moves freely, and Home frames the camera.
- The Passepartout (0 to 1) darkens the canvas outside the frame.
- While it is picked, Properties has a Camera tab: Position, Zoom and Roll, each with its key button, and Passepartout. Its keys show in the timeline under Camera, and under Selected while it is picked. The zoom's keys hold log2 of the zoom, so between keys it changes at a steady rate (from 1 to 4 it passes 2 halfway).
- Renders show exactly the frame. Python: oanim.data.camera (position, zoom, roll, passepartout, selected, keyframes(), to_frame()).

**Viewport toolbar.** A Blender-style toolbar runs down the left side of the viewport. Which tools appear depends on the active layer type: Box Select and Cursor are always there, and Draw, Split Curve and Knife appear for vector layers.

**Selection keys, as in Blender Grease Pencil edit mode.**

- **1, 2, 3** switch the selection mode: Points, Edges (clicking a line selects the segment between two points) or Strokes (clicking a line selects the whole curve). In Points mode only points are picked: clicking a line between them selects nothing. With edges selected, the Shape tab's Edge panel hides or shows their outline, as Moho's Hide Edge does. Clicks pick lines where they show (posed by bones, and a reference matching its original where that is). Curve handles show only in Points mode: Edges and Strokes modes pick lines, so their handles are hidden.
- **L** selects the whole shape under the mouse; **Shift+L** deselects it.
- The **Points, Edges and Strokes** buttons in the header show only when there are points to pick.
- **Shift+Z** over the viewport shows or hides its overlays (bones, wires, points, handles), as the header's Overlays button does. A selected camera still shows its frame.

**Two cursors.** Camera view has a 2D cursor on the canvas and World view has a 3D cursor in the scene. They are separate, and each keeps its own position. New layers, bones and imported meshes are placed at the active view's cursor, and the cursor can be the pivot point.

**Move, rotate, scale.** G moves, R rotates and S scales from any tool, as in Blender. Angles are plain numbers, as in Moho: R counts whole turns while the mouse circles the pivot, and layer rotation and bone angles key any amount, so one key at 720° spins twice. On points, S and R work about the middle of the selection's bounds (so S X -1 flips them in place, as Mirror Local does). For bones, S on frame 0 resizes them (their joints spread about the pivot, so bones get longer; scale stays 1). Posing, S scales each bone along its own axes: S X its thickness, S Y its length, and S S squashes and stretches (longer and thinner, keeping its area). Bone transforms take X / Y and typed numbers too.

- Then press **X, Y or Z** to lock to that axis; press it again to switch to the other orientation. **Shift+X, Y or Z** locks to the other two axes.
- Type a number for an exact value, as Blender's numeric input: once anything is typed the mouse stops moving it. Move has an X and a Y field (Tab goes to the other; along X or Y there's one), Scale one for every way (Tab to give Y its own), Rotate degrees. Minus flips the sign (before or after the digits), Backspace takes back a character and Ctrl Backspace the field; the header shows the field being typed as [1.5|]. Points, layers, bones and media all take it. Hold Ctrl to snap, Enter or click to confirm, Esc or right-click to cancel.
- **Alt S** with points selected scales the line's width at them (Blender Grease Pencil's Shrink/Fatten): away from their middle fattens, towards it thins, each point's radius scaled by the same factor; a typed number sets it, Ctrl snaps to tenths, Esc puts them back. A point's radius goes up to 10 times its shape's line width (Mean Radius in the Point panel too). On a Media layer Alt S is still Clear Scale, on a bone layer the bones'.
- Points and bones lie flat on their layer, so Z applies to things with depth: layers, the camera, the 3D cursor and meshes.

**Header dropdowns.** The viewport header carries Blender's three transform controls.

- **Transform orientation:** Global, Local (the layer's own axes), Parent (the parent bone), View or Cursor. Comma opens it as a pie menu.
- **Pivot point:** Bounding box centre, Median point, Individual origins, Active element or Cursor. Period opens it as a pie menu.
- **Proportional editing:** points only; the toggle and its dropdown show only while the edited layers have points. O toggles it. The dropdown, as Blender's panel, picks the falloff (Smooth, Sphere, Root, Inverse square, Sharp, Linear, Constant, Random; Shift+O cycles), Connected only (Alt+O: measured along the curves, so only points on a curve with selected points move) and the Proportional Size (0.2 to start). Scroll the mouse wheel (or Page Up / Page Down) during G, R or S to resize the influence circle drawn about what moves. Blender's Projected from View is left out: a drawing is already flat. This replaces Moho's Magnet tool.

**Materials.** Shared looks for shapes, as Blender's materials (Moho's library styles, Illustrator's global swatches). A shape has its own look, or is linked to one material, which then sets everything about its look: fill colour, line colour, line width and brush (Fill and Outline on/off and the points' widths stay the shape's). Changing a linked shape's look in the Material panel (its Brush section too, or Python) changes the material, and every shape using it changes with it. Which you're editing is plain to see: the panel's header, even folded, says "Material: Skin (shared by 12 shapes)", or "Material: Own look"; while one of a shared material's fields is under the mouse or being changed, every shape using the material is outlined in the viewport and the header says "editing Skin changes 12 shapes". Linked shapes carry a white corner mark (Illustrator's global swatch triangle) on their swatch in the Shapes list, on the browse button and in the materials list. The Shape tab's Material panel (folding, under the Shape panel, which keeps Name, Position and Fill / Outline) holds the look: its first row is Blender's data-block selector, then Fill Color, Line Color, Line Width and the Brush row (below). Each of those has an **eyedropper** at its right end: click it, then a shape in the viewport, and the selected shapes take that shape's fill colour, line colour, line width or brush (the colour picker's own eyedropper samples a pixel instead). Python: oanim.ops.mesh.style_copy_from(layer=, shape=, what=FILL|LINE|WIDTH|BRUSH). The selector: a browse button (the shape's swatch, a disc of its fill ringed in its line colour) opens the list of materials, each with its swatch and how many shapes use it (unused ones greyed out), a search field at the bottom (typed into as soon as it opens) and Remove Unused; hovering one outlines its shapes in the viewport, clicking links the shape, right-click > Delete Material. Beside it, the material's name (rename it there; names are made unique, "Skin.001") and the user count: clicking the count gives the shape the look as its own (unlinked, looking the same). With its own look the row is browse and **Make Shared**, which makes the look a shared material and links the selected shapes; right after leaving a material, New names the variant after it ("Skin.001"). Nothing is deleted on its own: a material no shape uses stays until Remove Unused, and deleting a material leaves its shapes its look as their own. A duplicated layer's shapes share their materials; a reference's copies take theirs from the original (the row is greyed out there). Saved with the project. The Moho converter brings looks in as each shape's own. Python: oanim.data.materials, layer.shape_material(i), oanim.ops.material.new / assign / unlink / rename / remove / remove_unused.

**Line weight at any zoom.** A line keeps its true weight however far the view (or a render) is zoomed out: one thinner than a pixel is drawn a pixel wide and as much fainter, rather than every hairline looking a pixel thick; a brushed line's stamps fade so that, overlapping, they come to its thinness. Masks still take hairlines a pixel wide.

**Brushes.** Open Animate copies Moho's stamp brushes: a line can be drawn as a row of image stamps instead of a solid stroke. A brush is part of a line's style, so shared styles share their brush. The stamps stick to the artwork: they are laid out along the line as drawn on the setup frame, each at a place on one of its segments, and kept at that place as points move and bones bend the line, so they stretch and squash with it instead of sliding along it (Moho's slide as a curve stretches; Toon Boom's textured lines are fixed to the line like this). A segment stretched past 1.5 times its length fades in stamps halfway between its own (and again at 3 times, ...), and one squashed below three quarters fades out every other one, so a line never breaks into dots or clots, after Bénard et al.'s self-similar line textures. Brush Settings' When Stretched picks whether those stamps fade (the default) or pop in and out whole. The layout doesn't depend on the zoom, so the viewport and renders agree.

- **Brush row**, in the Material panel: a preview stroke in the line colour, named in its corner by the preset it matches ("Ink"), or "Custom" when it matches none (edited since, or never one), or "Solid line", with Blender's **preset button** (three sliders, as tall as the preview) at its left. The button opens Brush Settings on its settings; clicking the preview opens it on the presets (the Brushes tab). In the preview's bottom right, the **brush eyedropper**: click it, then a stroke in the viewport (anywhere on it as drawn, its width included), and the selected shapes get that shape's whole brush, as one undo step (Esc, right-click or a click off any shape stops it; the cue at the mouse says so). The Draw tool's header has a button for the brush new strokes get, opening it on the tool.
- **Brush Settings window**, after Photoshop's Brush Settings and Brushes panels. It floats over the app and doesn't block it, so the viewport shows every change as it's made, and says what it edits ("3 selected shapes", "The Draw tool's brush"). It follows the selection: it shows the active shape's brush, and a change goes to every selected shape as just that setting, so they keep their other differences. Two tabs:
  - **Brush Settings:** Photoshop's sections down the left, each with its switch (a section switched off keeps its values): Brush Tip Shape, Shape Dynamics, Scattering, Color Dynamics, Transfer, Line Boil. The chosen one's settings are on the right and a large preview stroke runs along the bottom. Brush Tip Shape has the tip grid (None, a solid line; the built-in **Round** tip; the library's shapes; shapes only this file's presets carry; picking a shape changes only the shape, every setting stays), Angle and Roundness beside Photoshop's angle widget (drag to turn the tip; Ctrl: 15 degree steps), Flip X / Y, Hardness (the Round tip's), Spacing, When Stretched (Fade In or Pop In), Merge alpha, Tint and Random stamp order. The line's width isn't a brush setting: it stays the material's Line Width, and presets don't keep it.
  - **Brushes:** the presets as cards of preview strokes, the Project's and then the library's, grouped by category, the folders of Brushes (Photoshop's brush folders), each folding (Project and Basic open to start with, the rest folded), with a search field that shows matches in every group. Hovering a card shows it on the shapes until the mouse leaves; a click loads it; right-click has Save to Library (a submenu of categories, plus New Category...) and Delete; clicking a library category's header makes it where new library brushes go.
  - Along the bottom of both, Substance Painter's save row: a name field, where it goes (**Project** or **Library**, remembered), with Library a second dropdown of categories (the library's folders, the last one used, and New Category..., which turns it into a box to type a new folder's name), and +. Library is greyed out without an asset library. Saving opens the group it went to and scrolls to its card; the status bar says where it went and whether its shape was copied into Brush Shapes. Library brushes always have a category (My Brushes when none is named).
- **The built-in Round tip** (Photoshop's General Brushes: hard to soft by Hardness) is drawn by the app, so it's never missing and nothing is bundled.
- **Brush presets:** a shape plus every setting, saved by name (as Krita keeps presets apart from brush tips). Library brushes live in `<library>/Brushes/<Category>/<Name>.oabrush` (one JSON file each, a folder per category), for every project; built in are Hard Round and Soft Round (Basic, on the Round tip, which can't be deleted); project presets are saved in the .oanim, each with a copy of its shape's images, so a file always carries what its presets need. They're listed in the Brush Settings window's Brushes tab (above). Loading copies the settings in (nothing stays linked, so deleting a preset never changes what used it), so it follows materials like any edit. Names never clash: a taken name gets a number ("Ink.001"), no question asked. Saving to the library copies the shape too when the library lacks it; the same images under that name are reused, other images get the copy a number ("CK Ink.001") and the saved preset points at it. A preset whose shape is missing is greyed in the menu with a warning; loading it keeps your shape, applies the rest and says so in the status bar. Python: oanim.assets.brush_presets(library=False); oanim.ops.brush.preset_add (library="1", category=) / preset_load / preset_remove / preset_save_to_library (category=), oanim.assets.brush_categories(), oanim.ops.brush.setting_set(setting=, value=) for one setting on every selected shape (target="TOOL" for the Draw tool's brush), oanim.wm.brush_settings_open().
- **Brush shapes are only images:** `<library>/Brush Shapes/<Name>.png` is a shape of one image, a folder of PNGs a multi-image shape (used in turn, or at random). They carry no settings: the look is the brush's (its preset). Stamps are dark ink on white (darkness is coverage), or colour with alpha for colour brushes.
- **Asset library:** all of the app's brushes live in one asset library folder, set in Preferences (`<library>/library.json` marks it, format version 2; `<library>/Brushes/` holds the brushes by category, `<library>/Brush Shapes/` their images). If none is set, or its folder is gone, Open Animate asks for a folder at startup and initializes the library there. Preferences shows how many brushes and shapes it has, with Reload. Nothing is imported from Moho any more.
- **Upgrading an older library:** a version 1 library (Moho's brushes in `Brushes/`: `.mohobrush` files, PNGs with settings in their names like `Brush522_1_0_200.png`) is upgraded the first time it's read. Each brush's images become a shape under its own name (so documents using it still find it) and its settings a brush file named after it (without the settings in the name: "Brush522"), sorted into a category by what it looks like: Basic, Ink, Texture, Hair & Fur, Nature or Fun (others: Other). The old folder is set aside while that happens and deleted once everything is copied; if anything fails, it's kept as "Brushes (old)" with a warning.

**Detail levels (multiresolution shapes).** A shape can be edited with fewer or more points without losing its look, as Blender's Multiresolution modifier and ZBrush's subdivision levels do for meshes and Finkelstein and Salesin's multiresolution curves do for lines: the overall sweep is edited at a low level while the fine detail rides along.

- **Levels.** Level 0 is the shape's own points (what bones, weights and Parent Bone act on). A detail point at level k lives on one segment of level k-1: where it sits along the segment and how far it stands off it, measured along and across the segment and scaled with its length (Stretch: a segment twice as long has its detail twice as wide and twice as tall, so scaling a shape scales its detail and a shrinking segment never makes spikes). Its handles are kept the same way. Moving, bending or stretching the coarse curve carries the detail with it. Bones move detail points by their own weights, which they get from their neighbours as any new point does. A parent's handle facing finer detail is shown and edited as its handle at its own level (its coarse handle, longer than the piece it shapes); lines draw with the handles the splits give.
- **Per shape.** Each shape keeps its own level, saved with it; changing it is an undo step (Detail Level). Each shape's curves show their points up to its level (base points drawn bigger, the level's own at normal size, finer ones hidden); a curve shared by shapes at different levels uses the higher one. The full detail always shows and renders. Points hidden by stepping down are deselected.
- **Adding detail: the knife only.** Nothing subdivides on its own: the Split Curve tool (K) adds every detail point. At a level above a shape's top level (stepping one past it opens an empty level, with the hint "Knife (K) adds detail points at this level") the knife adds a detail point at the shape's level, on that segment only; at level 0 it adds a base point as it always has.
- **Where it is set.** The viewport header shows Detail ‹ 1 / 3 › (arrows, drag or type) while a shape is selected; with several selected at different levels it shows a dash, and setting it puts them all on that level. Ctrl+0 to Ctrl+4 set the selected shapes' level (with none selected the status bar says "Select a shape first"); Alt+Page Up and Alt+Page Down step it. The viewport's info text adds the active shape's level (Detail 1/3). The Shape tab's Shape panel has a Detail section: the same Level field, the shape's levels and detail points (Levels 3 · 14 detail points), Delete Higher (the detail above the current level), Apply Detail (flatten it into base points) and Rebuild Levels (turn a dense drawing, such as a Moho import, into a base plus detail: its detail flattened first, each point within the Tolerance of the curve its neighbours make without it becomes detail; when none can, nothing changes), each on the selected shapes and undoable. Apply Detail and Rebuild Levels work on the setup frame; keys they can't keep (a detail point's offsets) are removed, and the status bar says so. Python: layer.detail, oanim.ops.mesh.detail_level_set(level= or delta=), detail_delete_higher, detail_apply, detail_rebuild(tolerance=); layer.split_segment adds detail at the curve's level.
- **Wires** show each curve at its shape's level: through the points shown, with their handles as they are at that level, so the wire is what you bend; the stroke under it draws all of its detail. Clicking a line in Edges or Strokes mode picks that same curve.
- **Animation.** Detail points key like any point, relative to the setup pose and in their segment's frame, so animating the base points carries the detail and a lower level is the place for big moves.
- **Smooth to Lower Level** (right-click with detail points selected) moves them, or handles of detail points picked on their own, onto the curve of the level below, so they keep none of their own offset; the ViewportActionPanel's Influence (0 to 1) sets how far. Away from frame 0 it poses them (auto-key keys it). Python: oanim.ops.mesh.detail_smooth(influence=).
- **Move to Higher Level** (right-click with points selected) moves them one detail level up, keeping the curve's look (their places along the segment between the coarser points around them worked out anew), so they ride those points and hide below their level. An open curve's ends, points on more than one curve and points at the top level stay (the status bar says how many); a closed curve keeps at least two coarser points. Setup frame only; their keys go (as Rebuild Levels'). Python: oanim.ops.mesh.detail_raise().
- **Editing the base.** Deleting a base point joins its two segments and their detail moves onto the joined one (the status bar says so: "Merged the detail of 2 segments"); splitting a segment at level 0 gives each detail point to the half it is on. Symmetrize, mirror editing, references and smart actions treat detail points as points (each has an id).

**Media layers.** A Media layer shows an image, a numbered image sequence, a video or a sound, read with Windows' own decoders (WIC for images, Media Foundation for video and sound: what plays in Photos and Media Player opens here).

- **Adding one takes a drop, no dialog.** Drop a file on the viewport and it becomes a Media layer above the active one, starting on frame 1; dropped on the timeline, it starts on the frame it lands on; dropped on a Media layer's clips row, it joins that layer as a clip there instead (picked, over what was there). While the file is still being dragged, it shows live where it would land: in the timeline a dashed bar as long as the clip it would make, at the frame under the mouse ("Add clip walk.mp4: frames 81 to 128" on a clips row, "New Media layer ..." elsewhere), and over the viewport the outline of its picture fitted to the camera's frame with what it is (Open Animate's own drop target reads the files as the drag enters; SDL's names them only on the drop). File > Import > Media and the Layers editor's + > Media... do the same with a file dialog. A numbered image ("walk_0001.png" with siblings) comes in as an image sequence. Named after the file. Its options then show in the ViewportActionPanel: Start Frame, Fit, Opacity, Guide; the Properties editor turns to its Media tab.
- **Tracing defaults.** A guide (Show in Renders off: shown while you work, hidden with the overlays, never rendered, as After Effects' guide layers and Blender's reference images), at half opacity, fitted to the camera's frame (at zoom 1). Clicking in the viewport never picks it, so drawing over it is safe; it is picked in the Layers editor or the timeline, and the Select tool says to add a vector layer above it to draw. With it active, G, R and S move, turn and scale the layer itself, as Blender does an object (about its picture's middle; X or Y keeps to one axis, Ctrl snaps, a typed number sets it; keyed away from frame 0), and Alt G, Alt R and Alt S clear its Location, Rotation and Scale (0, 0 and 1), as Blender's Clear Location, Rotation and Scale.
- **Clips.** The layer holds clips along the timeline, as a video editor's track: each is a file shown from its Start for its Length, from In seconds into the file (After Effects' in point). A new clip is as long as its file (a still image: to the end of the frame range). Clips never overlap: one moved or trimmed over another overwrites it. Changing the file part way through the animation (Replace from Current Frame) ends the clip there and starts a new one. After End says what a clip shows once its file runs out (Hold Last Frame, Loop from its In point, or Hide). Timing: Real Time (a 30 fps video plays at its own speed in a 24 fps scene) or Frame by Frame (one video frame per scene frame, for a reference made at 12 fps; its sound follows the speed); a sequence is always one image per frame. The setup frame shows what frame 1 does.
- **Media tab.** A picture of the frame showing, the file's name and what it is ("Video, 1920 x 1080, 30 fps, 4.2 s, with sound"); Replace... (another file, the clip's timing kept, as After Effects' Replace Footage), Reload, Pack / Unpack, Replace from Current Frame...; the Clip panel for the clip on the current frame (else the one picked in the timeline, else the nearest, saying which frames it is on): Start, Length, In, After End, Timing, and its timing in words ("30 fps video in a 24 fps scene: plays in real time"); Look: Guide, Fit (Fit, Fill, Stretch, Original Size), Opacity (keyable), Greyscale, Tint Color and Tint (a light table's look: the dark parts take the tint, the light stay white, as blue-line pencil), In Front (over everything, unmasked); Sound (when it has some): Volume, Mute.
- **Timeline.** While a Media layer is active, Selected shows its clips (a row two rows tall) and its own keyed channels (where it is, its opacity). Each clip is a bar: a filmstrip of its file (made in the background, so playback never waits for it), a waveform for sound, its name, and hatching past the file's end (Hold, Loop, Hidden). Clips move and trim as in ToonSquid: a click picks a clip (Shift adds), framing it in light blue with a dark pill handle at each end; dragging a clip moves it (an unpicked one moves whole, even grabbed near its edge), the picked clip's handles (grabbed wider than they are drawn) trim it, and Alt-drag slips it (the bar stays, the part of the file shown moves); the cursor says which, and while trimming or slipping the whole file shows faded behind it. Without the magnet no other clip changes, as ToonSquid's timeline with its magnetic mode off: a handle stops at the neighbouring clip, and a clip dropped on another is outlined red and goes back ("hold Ctrl to push the others along"). Holding Ctrl while dragging turns the magnet on, as ToonSquid's magnetic mode: trimming the end carries the clips stuck to it (no gap) along and pushes those it runs into, trimming the start retimes the clip before it (they stay together, or it gives way), a moved clip pushes the clips it lands on along, and edges snap to the playhead, the frame range's ends and other clips' edges ([ToonSquid handbook: Timeline](https://toonsquid.com/handbook/interface/timeline/)). Python: media.clip_drag (kind MOVE, TRIM_START or TRIM_END; magnet). A readout follows the mouse ("Trim   Start 1   Length 47   End 47   In 0.00 s"). Each drag is one undo step (Move, Trim or Slip Clip); Esc or a right-click puts it back. X or Delete over the timeline deletes the picked clips (Shift-click picks more); with none picked it deletes keys as before. Right-click a clip: Replace..., Replace from Frame N..., Split at Frame N, Delete Clip, After End, Timing (and Locate... when its file is missing).
- **Files.** Linked by default, saved with an absolute path and one relative to the .oanim, and found from either (a moved project folder still opens). Pack keeps a copy inside the .oanim (`media/<id>/<name>`, stored, not recompressed) so it opens anywhere; Unpack goes back to the file, writing it beside the .oanim (media/) if it is gone. A missing file shows: a red mark on its layer in the Layers editor, a red striped clip ("Missing: walk.mp4") and a Locate... button in the Media tab; opening a project with missing files says so once in the status bar (no dialog in the way). Locate finds the file, and every other missing file in that folder with it (Premiere's Relink Others Automatically).
- **Decoding.** Each video decodes on a worker thread of its own, as Blender's movie clip cache does: a frame asked for seeks to the keyframe before it and decodes forward, then a little further ahead, so playback finds its frames waiting (cached by time, so variable frame rates work). Until the exact frame is ready the nearest decoded one shows, never a blank; a render waits for the exact one. Pictures are halved until their longer side is at most 2048 pixels. Sound decodes whole, in the background, to 48 kHz stereo.
- **Sound.** Anything with sound plays it with the animation (forward playback, as in Blender), mixed from every Media layer at its Volume; Mute silences one. The timeline's Playback popover has Blender's Audio settings: Scrubbing (a frame's worth of sound each time the frame changes while scrubbing) and Play Audio, and Sync: Play Every Frame, Frame Dropping, or Sync to Audio (the frame follows the sound being heard). Python: oanim.media.probe(), pixel() and mix(), Layer.media_clips and media_shown(), and the media.* operators (add, clip_add, replace, replace_from_frame, reload, pack, unpack, locate, clip_set, clip_split, clip_delete).

**Multi-layer editing.** Select several vector layers in the Layers panel (Ctrl-click one at a time, Shift-click a run of them) and the point tools work on all of them at once.

- Points of every selected layer are shown and selectable; the active layer is highlighted, the others drawn slightly dimmer.
- Box and lasso select pick points across all selected layers in one drag.
- Move, rotate and scale (including G, R, S) transform every selected point together around one shared pivot. Each point still moves correctly inside its own layer, even when the layers have different transforms or bones.
- Curvature, line width, delete, and the sculpt brushes also act on all selected layers.
- On an animated frame, keys are set in each layer that changed. The whole edit is one undo step.

**Built-in MCP server.** Open Animate can be driven by AI assistants such as Claude through the Model Context Protocol, so they can look at and work in the running app. Moho has no such thing, which is why MohoMCP has to poll for requests inside a tool's draw call; here it is part of the app. The first version is deliberately thin while the API is still changing.

- **Built on what already exists.** Everything goes through the `oanim` Python API and its operators, so anything a person can do, the server can do, with the same undo steps.
- **Tools now:** run Python with the `oanim` module (as a console: names stay between calls, the last line's value, printed output and tracebacks come back); a screenshot of the window or one editor; the app's state (file, frame, playback, layers, selection, a running transform, recent Info reports); and pressing keys as if over an editor (typed numbers go into a running transform). Later, once the API settles: typed tools to read the document, layer tree, bones, actions and keyframes, get and set properties by path, run operators by name, set and delete keys, switch frames and actions, render a frame, and run several operations as one undo step.
- **Resources (later):** the `oanim` Python API reference and the operator list, so an assistant can discover what is available.
- **Transport:** JSON lines on 127.0.0.1 only (`src/wm/remote.cc`), run on the app's main loop between frames (screenshots from the frame just drawn), so no polling; a stdio bridge in plain Python using only the standard library (`tools/mcp/openanimate_mcp.py`) speaks MCP, registered for this project by its `.mcp.json`.
- **Safety:** off by default and switched on in Preferences (Remote Control); every request needs a token made afresh each time it starts (written with the port, the process id and the open file to remote/<process id>.json in the user data folder, one per running Open Animate, and to remote.json by the one holding Preferences' port, where the bridge reads them; removed when it stops, and left-over files of instances that crashed cleared). Several windows can each be reached: a second Open Animate takes a free port, and the bridge's list_projects names every open project while each tool takes `project` (a file name, path or process id), the main one otherwise; a connection that doesn't open with a request, as a browser's doesn't, is closed unread. Later: a separate switch for running Python and a status-bar indicator while an assistant is connected.
- **How it is built:** the listener in C++, the bridge in plain Python outside the app (no MCP SDK needed: MCP's stdio protocol is small), tested end to end headless (`tests/test_remote_control.py`).

## Architecture sketch

The app is a small Blender: a C++20 core that holds the data and does the math, an operator and keymap layer that all editing goes through, and embedded Python for tools, panels and add-ons. We copy Blender's ideas, not its heavy infrastructure (depsgraph, multi-backend GPU module, raw-memory .blend files).

**Modules**

| Module | Responsibility | Blender equivalent |
| --- | --- | --- |
| `core/` | Math, containers, IDs, logging | `blenlib` |
| `data/` | Document, layer tree, vector drawings, skeletons, actions. Saved data kept apart from runtime caches | `makesdna`, `blenkernel` |
| `rna/` | Property reflection: name, type, range, getter/setter, update callback. Drives UI, Python and animation paths | `makesrna` |
| `anim/` | Animated channels, keyframes, interpolation, actions, smart bones, drivers | `animrig`, `fcurve.cc`, `constraint.cc` |
| `eval/` | Fixed evaluation pipeline that builds an evaluated copy of the scene each frame | `depsgraph`, simplified |
| `modifiers/` | Modifier type table: mirror, noise, smooth, offset, armature deform and more | `modifiers/` |
| `ops/` | Operator registry, macros, undo flag, redo panel | `windowmanager` operators |
| `wm/` | Windows, event loop, keymaps, modal handlers, split-area screen layout | `windowmanager`, `editors/screen` |
| `editors/` | One folder per editor: viewport, timeline and dope sheet, graph, layers, properties, outliner | `editors/space_*` |
| `gpu/` | OpenGL renderer, curve tessellation, overlays for bones, handles and onion skins | `gpu`, `draw` |
| `io/` | Native file format, image and video export, SVG import, mesh import | `blenloader`, `io` |
| `python/` | Embedded CPython and the `app` module | `python/` (bpy) |
| `scripts/` | Python startup scripts: UI panels, default keymap, theme, built-in Python tools | `scripts/` |
| `mcp/` | Built-in MCP server in Python on the official SDK; maps MCP tools to operators and properties; localhost HTTP plus a stdio bridge | None |

**Evaluation order, every frame**

1. Read each animated channel at the current frame from the mainline.
2. Apply smart actions: each driving bone's angle picks a frame in its action, and that action's values are layered on top.
3. Solve the bone pose: forward kinematics, IK, constraints.
4. Deform bound points and layers by their bones.
5. Run each layer's modifier stack.
6. Composite layers with masks and blend modes, then draw overlays.

**Key technical choices**

- **Window, input and tablet:** SDL3. **Graphics:** OpenGL 4.5 first; Vulkan only if needed later.
- **UI:** Dear ImGui with docking wherever it can do the job, themed with Blender's default colours, font and spacing. Custom widgets built on ImGui cover what it lacks or draws differently: Blender-style number fields (a click without dragging starts typing, a drag changes the value, Shift while dragging is precise), pie menus, tabs and icons. Panels are written in Python with a `layout.prop(...)` style API so the UI toolkit can be swapped later.
- **Python:** embedded CPython 3.12+ through pybind11, exposed as a `oanim` module shaped like `bpy`.
- **Operators:** each has `poll`, `invoke`, `modal`, `execute` and an UNDO flag, as in Blender. Extrude (E) is a macro: the data operator followed by modal move (G).
- **Keymaps:** data files of (operator, key event, properties) per editor and mode, modelled on Blender's `blender_default.py`.
- **Undo:** an operator with the UNDO flag snapshots the layers it changed, using copy-on-write so unchanged data is shared.
- **File format:** a .oanim file: a zip holding a JSON scene description plus binary blobs for point data, with a schema version and migration functions.
- **Build:** CMake with vcpkg for dependencies, on your installed MSVC 14.51 toolchain. Windows only for now; SDL3 and OpenGL keep a later macOS or Linux port possible.

**What a Python operator looks like**

```python
import oanim

class BONE_OT_smart_create(oanim.types.Operator):
    bl_idname = "bone.smart_create"
    bl_label = "Create Smart Bone"
    bl_options = {'REGISTER', 'UNDO'}

    @classmethod
    def poll(cls, ctx):
        return ctx.active_bone is not None and ctx.action is None

    def execute(self, ctx):
        bone = ctx.active_bone
        action = ctx.active_layer.actions.new(name=bone.name)
        action.smart_bone = bone
        ctx.document.edit_action(action)
        return {'FINISHED'}

oanim.utils.register_class(BONE_OT_smart_create)
```

## Roadmap

Version 1 arrives in five milestones, and each one ends with something you can actually use. No dates yet: the pace depends on how many hours a week go into it.

1. **Foundation:** CMake build, SDL3 window, OpenGL, ImGui docking, embedded Python; operator registry, keymaps, undo, split areas, reflection registry; command-line mode for scripts and tests; interface scale setting.
   *Gate: a Python operator runs from a key press and undoes cleanly.*
2. **Drawing:** vector layers (points, curves, shapes, styles, brushes) and the curve renderer; pen, freehand, select, G R S E, curvature, fill; save and open; Layers editor, group and reference layers, masks; snapping, autosave, crash recovery, Save Incremental, pen tablet support.
   *Gate: draw, fill and save a character that matches the Moho look.*
3. **Animation:** animated channels, interpolation modes, timeline and dope sheet; switch and image layers, onion skins, PNG export; frame-by-frame drawing, auto-keying, playback controls, render settings.
   *Gate: animate a walk cycle by hand and export it as PNG frames.*
4. **Rigging:** bones, point and layer binding, IK, custom bone shapes, bone colours; actions, smart bones, local armature viewport, symmetrize with _L and _R; Setup toggle for frame 0; copy, paste and paste-flipped poses.
   *Gate: a smart-bone head turn works on a rig with IK arms.*
5. **Version 1:** modifier stack and mirror modifier, free 3D view, layer depth; operator search, redo panel, keymap editing, Python console, MCP server; top bar menus, workspaces, Properties editor tabs, auto-generated API docs.
   *Gate: rig and animate a short scene end to end, no Moho needed.*

**After version 1:** graph editor, bone dynamics and physics, bone constraints, smart warp; weight painting, motion paths, pose library, asset browser, video export, mesh import.

Each gate is a hands-on test; a milestone is done only when its gate passes. Rendering quality is proven in milestone 2 and smart bones in milestone 4, the two riskiest pieces.

## Risks, open questions and references

The biggest risks are vector rendering quality and smart bones' interaction with IK; both get a prototype early, in milestone 2 and milestone 4.

**Risks**

| Risk | Why it matters | Mitigation |
| --- | --- | --- |
| Vector fills and strokes look worse than Moho's | Curves must tessellate into smooth, anti-aliased triangles every frame | Prototype the curve renderer first; compare against Moho screenshots; use multisampling |
| Smart bones fight IK and constraints | Moho samples actions after posing; order mistakes cause jitter | Follow the evaluation order in the architecture section; write regression tests from small rigs |
| UI work balloons | Blender's UI toolkit is huge | Start with Dear ImGui docking; keep panels in Python so the toolkit can change later |
| Python binding grows hard to maintain | Hand-written bindings for every class add up | Generate bindings from the reflection registry, as Blender's RNA does |
| Scope creep | 63 features is years of work | Ship each milestone; move features between tiers instead of adding them to v1 |
| Reference layers lose their link or gain stray keys | Advanced masking depends on references staying in sync; Moho users report both bugs | Store a per-channel override flag; test sync, override and break on nested groups in milestone 2 |
